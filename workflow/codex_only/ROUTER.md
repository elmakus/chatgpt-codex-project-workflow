# Codex-only Router

> M01 foundation contract. Root policy routing MUST NOT select this namespace before M04.

Classification: **adapt**.

## Policy boundary

This router is the future `codex_only` project router. It uses genuinely policy-neutral common authority and policy-local contracts only. It does not depend on another policy namespace or the legacy shared execution core.

## Foundation priority model

After activation, routing must recover durable state and prioritize, in order as applicable:
1. explicit Intake entry/recovery;
2. selected workstream/Task Board binding;
3. pending/in-progress formal review;
4. active/complete Research return obligations;
5. RED corrective routing;
6. post-review project-state finalization;
7. in-progress or READY execution;
8. milestone/workstream Close;
9. Planning/Definition/Research when accepted authority requires escalation.

Codex Main is the fixed project execution coordinator. Fixed-policy routing does not run a capability preflight and never changes execution policy automatically because of runtime convenience.

## Continuation

Completing one role is not a user stop. Deterministic authorized transitions continue through Codex Main until a real strategic/product, explicit authorization, non-remediable runtime/input or end-of-approved-scope boundary.

M02 finalizes review/recovery priority details. M03 adds bounded compatible-ready-set routing. M04 reconciles the full lifecycle router and performs root cutover only after namespace completeness is proven.
