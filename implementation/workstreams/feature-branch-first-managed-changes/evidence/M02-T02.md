## Implemented contract

- `EXECUTION_PREP.md` requires an exact validated branch-isolated workstream before active Task Board creation and scaffolds only `WORKSTREAM_TASK_BOARD_TEMPLATE.yaml`. Root `implementation/TASK_BOARD.yaml` and the root Task Board template are historical recovery/migration surfaces only.
- `STATE.md` rejects legacy/default as a normal active ChatGPT-only state context. Active mutable execution is manifest-bound workstream state only.
- `RECOVERY.md` owns deterministic historical root/default migration-before-mutation. The source root board stays read-only. Before any branch creation/adoption, Recovery must prove the exact `integration_target`, creation/adoption base and independent-versus-stacked dependency topology from durable project/Git/PR evidence using the policy-local Intake classification rules.
- Independent migration uses the normal integration target/base with null parent fields. Stacked migration requires exact parent-workstream/branch evidence plus a concrete parent-only dependency. Unprovable target/base/dependency topology fails closed before branch creation/adoption.
- The migrated manifest persists coherent `base_ref`, `integration_target`, `parent_workstream`, `parent_branch` and `parent_dependency`; branch readback validates both manifest ↔ Task Board binding and the proven topology before mutable ownership switches.
- Partial migration recovers the same deterministic identity **and topology** rather than creating a duplicate lane.
- `ROUTER.md` explicitly permits `INTAKE.md` only for the historical Recovery path that must recover/create workstream identity, target/base or dependency topology.
- `CLOSE.md` no longer finalizes an active root/default Task Board; historical root handoffs remain readable evidence.
- Task/card/template/repository surfaces no longer offer root/default as active scaffolding/state.
- Existing Card/milestone review ownership, implementation/recovery Research ownership, micro-fix proportionality, target refresh, stacked-workstream safety, terminal target-side package and source-branch-deletion semantics remain intact.
- M02 OpenSpec design/spec now includes the deterministic target/base/dependency topology invariant.
- `tests/test_chatgpt_only_branch_first_execution_state_contract.py` includes focused regression assertions for topology-before-branch creation in addition to the existing migration/default-state contract.

## RED finding reconciliation

The independent review of subject `775792e49d6b6a9e37cc60bdb14445269df9583a` found that historical migration could create/adopt a branch without first determining the exact integration target, base and dependency topology.

The bounded correction:
1. makes topology recovery precede workstream branch creation/adoption;
2. requires the same policy-local base/dependency classification used for normal Intake;
3. fails closed when target/base/parent/dependency facts cannot be proven;
4. persists and read-backs the resulting topology in the manifest;
5. makes Recovery's use of Intake topology rules explicit in the Router read set;
6. adds OpenSpec and regression coverage for the corrected invariant.

No accepted requirement, ADR, milestone outcome or Card scope was changed.
