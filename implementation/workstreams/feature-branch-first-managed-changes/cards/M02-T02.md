# M02-T02 — Migrate ChatGPT-only execution state and historical-default recovery

- Milestone: `M02`

## Authority slice

- Master Plan / milestone contract: `planning/BRANCH_FIRST_MANAGED_CHANGES_MASTER_PLAN.md#M02--ChatGPT-only-lifecycle-migration`
- Requirements: `requirements/BRANCH_FIRST_MANAGED_CHANGES.md` — REQ-BF-002..009, REQ-BF-011..014, REQ-BF-016..017 and ChatGPT-only part of REQ-BF-015
- Accepted decisions: ADR-BF-001, ADR-BF-002, ADR-BF-003
- Relevant OpenSpec: `openspec/changes/branch-first-m02-chatgpt-lifecycle/` as reconciled by M02-T01
- Accepted dependency results: M01 GREEN checkpoint; M02-T01 GREEN result/review

### Must preserve

- New or continued managed work uses the exact manifest-selected branch-isolated Task Board; root `implementation/TASK_BOARD.yaml` is historical recovery/migration input only.
- Existing historical/default state remains readable and must migrate deterministically/fail-closed before any further managed-change mutation; completed evidence/history is not rewritten merely for layout.
- Manifest ↔ Task Board identity binding remains exact and no mismatch may fall back to root/default state.
- Exactly one active Card per selected ChatGPT-only Task Board remains the normal execution model.
- Card/milestone independent review state stays Task-Board-owned; manifest review stays final-integration-review-only.
- Implementation/recovery Research remains selected-Task-Board-owned and record-driven.
- Micro-fix proportionality, target refresh, stacked-workstream safety, terminal target-side package, post-merge recovery and source-branch-deletion safety remain intact.
- Branch → pull request → merge remains mandatory for every managed change.
- ChatGPT-only lifecycle mechanics must not import Codex-only modules or semantics.

### Must not / rationale that must travel

Do not delete historical root/default files or convert them into a second active workstream. Do not make `PROJECT.md` a live migration registry. Do not weaken exact-subject review or target-refresh semantics to simplify migration.

## Dependencies

- M02-T01 GREEN.

## Outcome

ChatGPT-only Execution Prep, execution-state recovery and closure no longer treat root/default state as a normal active context. New work always materializes/uses the selected workstream Task Board, while historical live state has one deterministic migration-before-mutation path.

## Scope

### Included

- `EXECUTION_PREP.md`, `STATE.md`, `RECOVERY.md`, `CLOSE.md`, `MICRO_FIX.md` where active default-state assumptions remain.
- `TASK_CARDS.md`, ChatGPT-only task/card/board templates and `REPOSITORY.md` wording where needed to prevent scaffolding/selecting root/default state for new work.
- `ROUTER.md` / `WORKSTREAMS.md` only for coherent historical migration routing and binding.
- ChatGPT-only prompt/template surfaces required by the M02 lifecycle contract.
- Focused regression scenarios covering migration, review independence, target refresh and terminal recovery.

### Excluded

- Codex-only lifecycle migration (M03).
- Deleting or rewriting completed historical/default artifacts.
- Repository dogfood/README/general documentation closure (M04).
- Final workstream integration/merge to main.

## Acceptance

1. Execution Prep never scaffolds/selects root `implementation/TASK_BOARD.yaml` for newly authorized managed work; it uses the exact manifest-selected workstream board.
2. `STATE.md` no longer defines legacy/default as a normal active state context for managed work.
3. Encountering historical live root/default state routes to deterministic migration/recovery before mutation, with exact authority/result/evidence preserved and no overwrite of unrelated state.
4. Recovery never resumes a live managed Card directly on root/default state and never guesses a workstream when identity is ambiguous.
5. Task Card/template/repository contracts do not instruct new ChatGPT-only managed work to use root default cards/boards/handoffs.
6. Card/milestone review, implementation Research, micro-fix, target-refresh, terminal-package and post-merge/source-deletion semantics remain coherent.
7. Existing historical files remain valid recovery/history evidence and are not removed solely by this migration.
8. ChatGPT-only files do not import Codex-only lifecycle modules.
9. OpenSpec remains coherent and focused migration/regression checks are GREEN.

## Required tests / checks

Exact branch readback plus scenario/static checks for new-work board creation, historical-default migration-before-mutation, binding mismatch, review/Research ownership, micro-fix, Close/target refresh/terminal recovery, historical preservation and cross-policy separation.

## External write/readback needs

Repository branch writes only.
