- Milestone: `M03`

## Authority slice

- Master Plan / milestone contract: `planning/BRANCH_FIRST_MANAGED_CHANGES_MASTER_PLAN.md#M03--Codex-only-lifecycle-migration`
- Requirements: `requirements/BRANCH_FIRST_MANAGED_CHANGES.md` — REQ-BF-002..009, REQ-BF-011..014, REQ-BF-016..017 and Codex-only part of REQ-BF-015

- Relevant OpenSpec: `openspec/changes/branch-first-m03-codex-lifecycle/` as reconciled by M03-T01
- Accepted dependency results: M01 GREEN; M02 GREEN migration lessons; M03-T01 GREEN result/review

### Must preserve

- New or continued managed Codex-only work uses the exact manifest-selected branch-isolated Task Board; root `implementation/TASK_BOARD.yaml` is historical recovery/migration input only.
- Historical/default live state remains readable and must migrate deterministically/fail-closed before any further managed mutation; completed evidence/history is not rewritten merely for layout.
- Historical migration proves exact `integration_target`, exact creation/adoption base and independent-versus-stacked dependency topology before branch creation/adoption; ambiguous topology fails closed.
- Manifest ↔ Task Board identity binding remains exact and no mismatch may fall back to root/default state.
- Codex Main remains the sole shared Task Board/integration-state writer.
- Serial execution remains safe/default; bounded M03 batch semantics, frozen membership/base/order, post-batch review drain and recovery transitions remain intact.
- Exact-subject Card/milestone review attempts remain Task-Board-owned and independently tested; manifest review remains workstream final-integration-only.
- Implementation/recovery Research remains selected-Task-Board-owned and record-driven.
- Micro-fix proportionality, target refresh, stacked-workstream safety, terminal target-side package, post-merge recovery and Codex-only branch-deletion semantics remain intact.
- Runtime worker/session/model/worktree identity remains non-authoritative and absent from durable project schema.
- Branch → pull request → merge remains mandatory for every managed change.
- Codex-only lifecycle mechanics must not import ChatGPT-only modules or semantics.

### Must not / rationale that must travel

Do not delete historical root/default files or convert them into a second active workstream. Do not make `PROJECT.md` a live migration registry. Do not weaken Codex Main ownership, bounded-batch invariants, exact-subject Tester independence, target-refresh semantics or terminal cleanup safety to simplify migration.

## Dependencies

- M03-T01 GREEN.

## Outcome

Codex-only Execution Prep, execution-state recovery and closure no longer treat root/default state as a normal active context. New work always materializes/uses the selected workstream Task Board, while historical live state has one deterministic migration-before-mutation path that preserves Codex Main, bounded-batch and Tester semantics.

## Scope

### Included

- `workflow/codex_only/EXECUTION_PREP.md`, `STATE.md`, `RECOVERY.md`, `CLOSE.md`, `MICRO_FIX.md` where active default-state assumptions remain.
- `TASK_CARDS.md`, Codex-only task/card/board templates and `REPOSITORY.md` wording needed to prevent scaffolding/selecting root/default state for active managed work.
- `ROUTER.md` / `WORKSTREAMS.md` only for coherent historical migration routing, exact topology and binding.
- Codex-only bootstrap/handoff surfaces required by the M03 lifecycle contract.
- Focused regression scenarios covering migration, Main ownership, bounded batches, Tester independence, target refresh and terminal recovery.

### Excluded

- ChatGPT-only lifecycle migration (M02, already GREEN).
- Deleting or rewriting completed historical/default artifacts.
- Redesigning the existing bounded-batch or independent-Tester model.
- Repository dogfood/README/general documentation closure (M04).
- Final workstream integration/merge to main.

## Acceptance

1. Execution Prep never scaffolds/selects root `implementation/TASK_BOARD.yaml` for newly authorized/continued managed Codex-only work; it uses the exact manifest-selected workstream board.
2. `STATE.md` no longer defines legacy/default as a normal active state context for managed work.
3. Historical live root/default state routes to deterministic topology-before-branch migration/recovery before mutation, with exact authority/result/evidence/review/batch state preserved and no overwrite of unrelated state.
4. Recovery never resumes a live managed Card directly on root/default state and never guesses workstream identity/topology when ambiguous.
5. Task Card/template/repository contracts do not instruct active Codex-only managed work to use root default cards/boards/handoffs.
6. Codex Main sole-writer ownership, bounded batch/post-batch drain semantics and exact-subject independent Tester review remain coherent.
7. Implementation Research, micro-fix, target-refresh, terminal-package, post-merge and branch-deletion semantics remain coherent.
8. Existing historical files remain valid recovery/history evidence and are not removed solely by this migration.
9. Runtime identity remains outside durable project state.
10. Codex-only files do not import ChatGPT-only lifecycle modules.
11. OpenSpec remains coherent and focused migration/regression checks are GREEN.

## Required tests / checks

Exact branch readback plus scenario/static checks for new-work board creation, topology-before-branch historical migration, binding mismatch, Main sole-writer ownership, bounded batch + review drain preservation, Tester independence, Research ownership, micro-fix, Close/target refresh/terminal recovery, historical preservation, task/template surfaces, runtime-identity exclusion and cross-policy separation.

## External write/readback needs

Repository branch writes only.
