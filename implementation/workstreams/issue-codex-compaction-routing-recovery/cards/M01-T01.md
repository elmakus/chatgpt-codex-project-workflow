### Must preserve

- Durable orchestration state is only the manifest-owned opaque `runtime_owner + policy_ref + optional contract_fingerprint` binding.
- The current-context binding latch is conceptual and non-durable; durable binding/fingerprint evidence never implies the latch.
- Same-version reconstruction remains a re-bind trigger; version/fingerprint drift is only an additional stale-binding case.
- Concrete worker/session/process/model-instance/invocation/resume/worktree identity remains outside Project Workflow state.
- Existing review, authority, ownership, Task Board/workstream binding and real-stop state remain in their canonical owners.
- `codex_workflow` remains authoritative for interpreting the opaque policy reference and concrete role→harness/model realization.

### Must not / rationale that must travel

- Do not encode Muse-specific or any concrete role→harness/model mapping.
- Do not create a global orchestration registry or mirror binding state into `PROJECT.md`, Task Board or Task Cards.
- Do not make the latch durable or infer it from a matching fingerprint.
- Do not change `chatgpt_only` behavior.
- Do not wire route-specific dispatch/lifecycle transitions in this Card; that belongs to M01-T02.

## Outcome

The repository has one precise persistent binding schema plus one compact static Codex-only recovery kernel that defines the non-durable current-context latch, bounded reconstruction read set, fail-closed re-bind precondition and runtime ownership boundary without yet changing every route-specific dispatch path.

## Acceptance

- OpenSpec coherently freezes the manifest schema, non-durable latch, reconstruction/re-bind contract, drift semantics, fail-closed behavior and Project Workflow ↔ runtime boundary.
- Workstream template exposes exactly `runtime_owner`, `policy_ref`, and `contract_fingerprint` under `orchestration`.
- Workstreams contract identifies that block as workstream-local routing/recovery metadata and forbids mirrors/concrete runtime lifecycle identity.
- Kernel states the bounded recovery set and requires current-context re-bind before policy-dependent realization whenever the latch is absent/uncertain, including same-version reconstruction.
- A matching fingerprint cannot establish the latch; changed fingerprint requires re-resolution.
- Missing/stale/unresolvable binding fails closed; no alternate/native harness is selected merely because routing context was lost.
- State contract no longer blanket-forbids durable policy/profile selection while preserving all concrete runtime-identity prohibitions.
- Existing repository contract tests remain GREEN and diff/readback shows no `chatgpt_only` semantic change.
