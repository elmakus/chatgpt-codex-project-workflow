## Findings

### R01-F01 — Exact gate subjects are shape/equality checked, not S05 identity validated

Severity: acceptance-blocking.

The Card requires A/B/C/D gates to bind exact prepared subjects through the accepted S05 identity/publication primitives and requires stale/unsupported gates to fail closed. The technical contract requires the repository/commit/path/blob tuple to be proven as a real exact Git identity, including safe path, 40-hex identities, repository match, reachability and commit:path == blob.

`pwv22_native_routing.exact_subject()` only checks that the four fields are non-empty strings and returns them. `satisfy_gate()` then accepts equality of those unchecked strings; `premium_d_subject()` uses the same unchecked path. It never calls S05 `exact_blob()` or an equivalent validator. Therefore two identical malformed or unbound subjects (for example non-hex commit/blob, unsafe path, wrong repository, unreachable commit, or commit:path/blob mismatch) can satisfy A/B/C/D, including Premium D.

The focused tests only exercise equality/staleness and do not falsify malformed/unbound exact identities.

Required correction: bind gate satisfaction to the accepted S05 exact-identity primitive (or an equivalent fully validated exact identity supplied under an explicit validated contract) and add negative tests covering malformed/unbound/wrong-repository/path/blob/reachability cases required by the Card/technical contract.

### R01-F02 — Ordinary owner routing is not native-epoch/admission fenced

Severity: acceptance-blocking.

The Card acceptance requires native owner/epoch binding through S05 primitives. R7 requires official native release provenance/admission before ordinary routing and requires unbound, ambiguous, legacy or unsupported state to fail closed.

`route_owner()` accepts any mapping whose `phase` is in `OWNERS`; it does not require or invoke S05 `admit_native()`, nor does it receive a previously validated admission token/epoch. Consequently a legacy/unbound mapping such as `{"phase":"planning"}` routes successfully to `planning`. `routing_fingerprint()` calls `route_owner()` and likewise has no native-admission fence.

The tests explicitly demonstrate routing from phase-only mappings, so current behavior is not merely an untested integration assumption.

Required correction: make ordinary native routing consume/prove S05 native admission (or a narrow explicit already-admitted value whose provenance is enforced by the API boundary) and add fail-closed tests for missing/legacy/unsupported/mixed epoch state.
