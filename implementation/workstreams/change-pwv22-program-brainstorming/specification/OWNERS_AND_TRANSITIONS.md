# PWv2.2 native semantic owners and transitions — M01-S01-T01

Card: `M01-S01-T01`. Specification output only. R7/P2 authority prevails.

## Owner model
Canonical truth is split by semantic responsibility. No owner may become a universal STATE file, event ledger, tracker projection, runtime journal, scheduler or model/session registry.

| Owner | Owns | May mutate | Must not own |
|---|---|---|---|
| Intake | managed intent/classification | bounded intake record | Card/Review state |
| Research | factual uncertainty and exact return | Research result/return locator | strategy/product intent |
| Brainstorming | questions/alternatives/promoted candidate intent | bounded revisions/promotion locator | repair authorization |
| Definition | accepted product/global intent and requirements | Definition authority/revisions | runtime identity |
| Planning | strategy/order/outcomes and Simplification Review disposition | Plan/gates | Results |
| Execution Prep | stable Cards, dependency bindings, bounded JIT | unstarted contracts/prep state | strategy invention/model selection |
| Execution | one exact active Card implementation subject | Card-authorized implementation/evidence | successors/authority/acceptance |
| Result | immutable semantic Card outcome | append new Result | mutable status/history edits |
| Review | exact-subject append-only Attempt + GREEN/RED evidence | own attempt/evidence | implementation/downstream choice |
| Finding | durable defect/deferral fact orthogonal to verdict | bounded finding reconciliation | conditional GREEN |
| Finalizer/coordinator | mechanically implied transition | narrow CAS/readback update | semantic verdict/new scope |
| Recovery | reconstruction/mechanical repair routing | proven mechanical repair state | guessed facts/legacy normalization |
| External-effect owner | obligation-local intent→attempt→readback→known/UNKNOWN | authorized effect record | secrets/blind retry/universal ledger |
| Integration owner | exact admitted Result set/order/compatibility | bounded integration candidate | constituent acceptance |
| Close | accepted integration/publication/readback completion | closure proof | all-DONE shortcut |
| Runtime | workers/sessions/worktrees/messaging/cleanup | disposable runtime state | legality/freshness/acceptance |

## Transition and return law
1. Resolve exact official native release provenance before ordinary native routing; unbound/legacy/unsupported fails closed.
2. Select the smallest semantic owner from durable facts. Runtime/model/session/worker identity never selects legality.
3. Intake factual uncertainty routes to Research; Research returns to its exact recorded owner. A consumed return is not replayed.
4. Brainstorming cannot authorize repair. Promotion is exact before Definition.
5. Definition owns product/global intent; Planning owns strategy/order/outcome; Execution Prep owns bounded realization detail.
6. Material Planning requires owner-dispositioned Simplification Review before freeze and never rewrites active/completed work.
7. A/B/C/D are exact-subject one-shot gates. D binds the prepared/read-back subject before first Execution; model advice is non-authoritative and B remains independent.
8. Initial Prep eagerly materializes all stable knowable Cards; JIT is only for genuinely future-fact-dependent shape. Strategy ambiguity returns to Planning.
9. READY is derived. Launch refresh verifies exact authority, accepted predecessor Results/verdicts/compatibility and named technical contract.
10. Current-governor program mutation is serial. Native parallelism requires explicit finite admission; overlap/uncertainty serializes.
11. Execution stays inside one Card envelope; Main reconciles one immutable Result. Workers cannot authorize successors/scope.
12. Review is subject-driven. Verdicts are only GREEN/RED; findings are orthogonal. Independence is subject-relative, never model-relative.
13. Acceptance-falsifying findings forbid DONE. Safe deferral requires positive proof no authorized pre-repair consumer uses the defective property. Unknown impact fails closed.
14. RED repair is automatic only inside accepted scope/strategy. Missing facts→Research; strategy/order/outcome→Planning; product/global intent→Definition.
15. Effects use intent→attempt→readback→known result; uncertainty is UNKNOWN and forbids blind retry.
16. Native evolution classifies preserve/revalidate/stale/Recovery. Unchanged implementation under revalidation preserves Result identity and appends evidence.
17. Mandatory Final Qualification Handoff precedes Cleanup→Targeted Hunt→Global identical-prompt Hunt→integrated reconciliation/repair→material-local impact→fresh eligible final acceptance.
18. Close requires accepted implementation/integration, target readback, durable confirmation and no remaining authorized obligation; Card/milestone completion is insufficient.
19. A unique deterministic next obligation auto-continues until a real owner/Premium/access/effect/blocker boundary.

## Acceptance/evidence boundaries
- Artifact identity = repository + immutable commit + repository-relative path + Git blob, reachable from accepted published ref.
- Dependency = exact accepted Result, not DONE; multi-input consumption additionally binds exact compatibility and required verdicts.
- Freshness is material-input-local; unrelated changes neither stale nor authorize.
- Canonical writes use expected-old/CAS publication plus target-side readback; lost responses are read back before retry.
- Obligation/Result interchange is typed runtime-neutral JSON; runtime correlation is non-authoritative.
- Git/GitHub is canonical; caches/compiler/trace/shadow DAG/frontier/helper correlation are disposable.
- Secrets never enter canonical state. Legacy states are negative fixtures only.
