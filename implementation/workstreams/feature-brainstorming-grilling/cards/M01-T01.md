### Must preserve

- Grilling is an interaction method inside Brainstorming, never a phase, authority layer, intake kind or workstream kind.
- Automatic activation is semantic: dependent user decisions, material ambiguity, or materially different solution paths; no numeric threshold.
- Lightweight/simple Brainstorming remains legal.
- `#grill` only forces the method for the active Brainstorming scope and never creates/recovers a workstream.
- `#issue` and `#feature` remain the explicit Intake directives.
- The current frontier contains only material unresolved user decisions whose prerequisites are settled; ask the whole current frontier together, number questions, and include an assistant recommendation for each.
- Agent-findable facts remain agent-owned work and use permitted tools/Research rather than being delegated to the user.
- Recompute the decision tree/frontier after every user round before exposing dependent questions.
- Persist only accepted choices, unresolved material decisions, material dependency relations and research needs sufficient for recovery; do not require the full transient tree.
- Normal completion requires material branches resolved or explicitly deferred/non-blocking.
- A clear user stop ends further grilling immediately and classifies unresolved remainder by materiality.
- Existing explicit Brainstorming → Project Definition promotion semantics remain unchanged.
- `wait-what` remains outside scope.
- ChatGPT-only and Codex-only receive equivalent Brainstorming semantics without cross-importing execution mechanics.

### Must not / rationale that must travel

Do not turn the manual control into router-precedence Intake behavior. `#grill` is meaningful only after an active Brainstorming scope is resolved; otherwise it does not create exploratory/workstream state.
