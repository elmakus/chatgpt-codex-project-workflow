## Acceptance

- Task Board review state has one unambiguous current attempt plus durable prior attempts; each attempt binds one immutable exact subject to `pending | in_progress | green | red` and durable evidence without runtime worker/session identity.
- Reviewable implementation records a semantic project implementation-owner role sufficient for RED to return through Main to the owning Executor; reviewer role/independence is represented semantically without encoding a concrete runtime worker.
- RED evidence is never overwritten by a corrected subject; corrected implementation appends a distinct attempt and a later review performs the full applicable authority/acceptance check.
- Reviewer/Tester cannot repair production or become the project-state writer; Codex Main alone persists shared review/Task Board transitions.
- Runtime resume or fail-closed replacement may continue the same unchanged review attempt; replacement alone never creates a new project review subject/attempt.
- Recovery distinguishes durable verdict from runtime liveness, recovers partial transitions fail-closed and never requires session/invocation/model/profile/lease identity.
- Codex-managed formal review does not require an additional normal-ChatGPT review.
- Default and branch-isolated Task Board templates express the same M02 review/provenance semantics and remain serial-safe.
- M03 parallel fields/algorithms are absent; root routing, `workflow/chatgpt_only/` and root execution policy remain unchanged.
- OpenSpec and implementation contracts are coherent; static scenario/schema/diff/conflict checks are GREEN.
