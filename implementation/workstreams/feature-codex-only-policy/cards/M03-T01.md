### Must preserve

- Serial execution remains fully valid when no parallel metadata is present or current-state safety cannot be proven.
- Planning may record candidate overlap but cannot certify runtime-safe concurrency; Execution Prep/JIT makes the current-state decision immediately before launch.
- Parallel eligibility requires completed dependencies, explicit `parallel_safe: true`, bounded/disjoint `write_scope`, non-conflicting `exclusive_resources`, isolated mutable workspaces for concurrent local mutation, and one exact recoverable integration base.
- A parallel run is one finite frozen compatible batch, not a continuously refillable/global scheduler.
- Codex Main remains the sole writer of the selected Task Board and shared integration state. Worker lanes return bounded result/evidence only.
- Project Workflow may persist semantic Card/lane ownership, exact Git integration base/result refs and evidence, but must not persist runtime worker/session/model/profile/invocation/lease/resume identity.
- Lane results must be verified against the frozen base and Card scope, integrated deterministically by Main, and remain recoverable after interruption.
- M02 immutable review-attempt, Tester non-repair, owning-Executor repair and runtime-identity boundaries remain unchanged.
- Intra-workstream concurrent local mutation requires the same worktree/equivalent isolation standard as cross-workstream concurrency.
- Root `workflow/CONTEXT_ROUTING.md` remains unchanged; `workflow/codex_only/` remains non-routable until M04.
- Existing `workflow/chatgpt_only/*` remains unchanged and this repository remains `execution_policy: chatgpt_only`.

## Outcome

The M02 codex_only execution/review state machine is extended with a bounded, deterministic, repository-recoverable parallel Card batch model. Current-state JIT may select multiple compatible READY Cards, runtime may realize their isolated lanes concurrently, and Codex Main alone records returned lane results and integrates them deterministically. Missing/unsafe metadata falls back to ordinary serial execution.

## Acceptance

- A Card with absent/default parallel metadata remains serial and valid.
- `parallel_safe: true` is only a candidate permission: JIT still proves dependencies complete, all write scopes pairwise disjoint, exclusive resources pairwise non-conflicting, isolated workspace availability for concurrent local mutation, and one exact recoverable integration base.
- The compatible set is finite/frozen before launch and is selected deterministically from current READY Cards; unsafe candidates remain eligible for deterministic serial execution rather than being silently dropped.
- Shared Task Board/integration state has one writer: Codex Main. Worker lanes cannot mutate shared coordination state.
- The selected Task Board durably records only project-level active-batch/lane/result/integration facts needed for recovery; no runtime identity/lifecycle state is required.
- Returned lane results are checked against the frozen base, bounded write scope and expected Card evidence before Main integrates them in frozen deterministic order.
- Recovery can distinguish prepared/running/returned/integrating/integrated/blocked members, preserve completed lane results, resume missing work once, and never infer obligations from runtime sessions.
- M02 review-attempt semantics remain intact for integrated Card results; a reviewable Card freezes its exact integrated result subject after Main-owned integration.
- Workstream/repository contracts require isolated mutable workspaces for intra-workstream concurrent local mutation.
- OpenSpec, templates and scenario audit agree; root routing, `workflow/chatgpt_only/` and root `execution_policy: chatgpt_only` remain unchanged.
