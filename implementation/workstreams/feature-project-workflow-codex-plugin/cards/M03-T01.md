## Acceptance

1. In a disposable repository with `pw@project-workflow` enabled and the accepted trust condition satisfied, an ordinary prompt with no explicit Skill invocation receives the Project Workflow bootstrap and routes through workspace `PROJECT.md` + canonical router.
2. The same invariant is preserved on a fresh session and on supported resume/compaction lifecycle transitions exercised by the current runtime.
3. A matched control repository without per-repository enablement does not receive Project Workflow activation.
4. Evidence demonstrates bounded progressive disclosure: startup injects only the small bootstrap/routing reminder, with route-specific authority loaded on demand rather than full workflow-policy preload.
5. `#feature` and `#issue` are each compared with their explicit Skill-argument equivalents under the enabled path. The durable supported convention follows PWCP-REQ-008/009 strictly from observed reliability.
6. `$pw:project-workflow` remains a working explicit general entry/recovery path.
7. Trust/install behavior is explicit and deterministic; any bypass exists only inside disposable test state.
8. Generic marketplace/update behavior is referenced rather than redundantly re-certified, while the Project Workflow-specific lifecycle delta is directly verified.
9. No live Codex marketplace/plugin/config/trust state is changed.
