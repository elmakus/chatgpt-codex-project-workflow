- Canonical Project Workflow files remain the only workflow authority; Skill/hook/bootstrap content may only route to them.

2. Existing generic Git-backed marketplace/plugin evidence is referenced and its reusable boundary is explicit.
3. An isolated current-runtime install proves a same-repository plugin source can carry the thin Skill/activation surface together with sibling canonical workflow files.
4. Installed activation code resolves canonical workflow paths from the installed plugin root without copied policy.
5. The chosen always-on candidate injects only a bounded routing reminder and does not preload canonical workflow contents.
6. Current-runtime evidence shows the candidate covers the accepted startup/resume/compact lifecycle contract sufficiently to proceed to M02, with full E2E lifecycle acceptance still owned by M03.
7. Trust behavior is explicit and reproducible.
8. Enabled/control behavior demonstrates that this feature does not silently govern a repository where it is not enabled.
9. No live Codex marketplace/plugin state is changed by the verification.
10. Evidence ends with a concrete M02 implementation contract or an exact hard-platform contradiction requiring Definition reconsideration.
