## R09-F01 — production obligation derivation is not bound to the registered rule's actual canonical determining inputs

`PolicyKernel.compile_obligations()` only checks that the rule ID exists, then forwards caller-supplied `role` and arbitrary `determining_inputs` into `compile_execution_obligation()`. It does not derive those inputs from the registered rule/canonical state and does not require the rule to match that state.

The shipped M02 test demonstrates the under-binding: PWV21-K011 declares `board.cards` as its canonical input, but the obligation is compiled with `{"board_revision": 8, "card_id": "M02-T01"}`. A material change to `board.cards` can therefore leave both freshness fingerprint and `obligation_id` unchanged if the caller repeats the same arbitrary mapping. The same seam can also compile a syntactically valid obligation with a semantic role unrelated to the registered rule outcome.

This violates the accepted P2 derivation/freshness contract and PWV21-REQ-019, PWV21-REQ-024, PWV21-REQ-025 and PWV21-REQ-028. It also weakens ADR-PWV21-001/002's requirement that PW, rather than runtime/caller convention, own deterministic obligation derivation.

Required correction class: bind the production kernel seam to the registered rule and current canonical state; derive the determining input material from that rule rather than accepting an arbitrary caller projection; reject rule/role mismatch; add regression cases proving material rule-input changes affect freshness while unrelated state does not.

## R09-F02 — the no-direct-canonical-mutation boundary is not enforced by the representable Result contract

`validate_execution_result()` accepts any syntactically valid `changed_artifacts` exact ref. A Result can therefore report a changed artifact in the obligation-subject repository at `PROJECT.md` or under `implementation/workstreams/**`, i.e. canonical Project Workflow durable state, and still validate.

The current negative test does not exercise this representable path. It adds an invented top-level `canonical_write` property and succeeds only because the schema is closed. That proves unknown properties are rejected, not that a direct canonical-state mutation expressed through the actual `changed_artifacts` field is rejected.

This violates the P2 no-direct-mutation acceptance surface and PWV21-REQ-032.

Required correction class: reject canonical PW-state artifact mutations through the actual Result artifact surface for the obligation-subject repository and add sibling tests for PROJECT.md and workstream-local durable state paths while retaining legitimate implementation artifacts in other repositories.

## R09-F03 — mandatory governed readback is not coupled to final fresh-result acceptance

The contract exposes `verify_mutation_readback()`, but the fresh-result acceptance path can still return `accept` for an obligation with non-empty mutation postconditions when the Result has no verified readback evidence (including an empty/failed `readback` list). The current mutation test invokes the helper separately, so it does not prove that mandatory readback gates the final accept path.

This leaves the accepted P2 requirement "governed write + mandatory readback/validation" dependent on caller convention rather than the M02 contract boundary, contrary to PWV21-REQ-031.

Required correction class: preserve stale classification before mutation, but require a verified governed readback/observed-state proof before a fresh result with mutation postconditions can reach terminal `accept`; cover missing, failed and mismatching readback variants.

## R09-F04 — exact-ref path validation admits non-canonical path aliases

Both the executable exact-ref validator and JSON schemas admit repo-relative path spellings such as `a//b` and `a/./b`. These are not canonical repository path spellings, yet the raw string is retained in the exact ref and therefore in serialized freshness/identity material. A reader that normalizes such spellings can resolve the same repository object through distinct ref strings, yielding distinct fingerprints/IDs for the same underlying exact location.

This is inconsistent with exact-ref validation and deterministic identity under PWV21-REQ-020/PWV21-REQ-024.

Required correction class: require canonical repo-relative POSIX path spelling in executable and schema validation and add alias-regression coverage.
