## Complete material finding set

### F1 — RED — freshness fingerprints are not minimal for collection-valued mechanical inputs

PWV21-REQ-025 and the M02 Task Card/P2 acceptance require Obligation/Result freshness fingerprints to contain only canonical inputs that materially determine the obligation and to remain insensitive to unrelated perturbation.

At a8350a1de2a98be92d56867f7f483cffdfd05f18, `PolicyKernel._rule_inputs()` copies each registry-declared input value verbatim into `freshness.material.inputs`. For PWV21-K011 and PWV21-K012 the declared input is the complete `board.cards` array.

That raw container is broader than either mechanical predicate:
- K011 (`board_one_ready_card`) inspects Card statuses only to decide whether exactly one Card is READY.
- K012 (`board_all_cards_done`) inspects Card statuses only to decide whether the board is non-empty and all Cards are DONE.

Consequently, changing non-determining Card metadata or merely reordering otherwise equivalent sibling Card records changes canonical JSON for `board.cards`, which changes the freshness fingerprint and `obligation_id` although the mechanical decision is unchanged and the exact subject/authority/prerequisite/completion/mutation bindings are separately fingerprinted. The current K011 regression also treats appending an unrelated DONE sibling as a required fingerprint change, demonstrating the same over-broad projection rather than guarding the accepted minimality invariant.

Impact: a valid result can be classified stale, and therefore forced into reconciliation/re-execution, due solely to canonical state that did not materially determine the obligation. This violates REQ-025 and the explicit M02 fingerprint-minimality acceptance criterion.

Required bounded correction: derive a minimal deterministic freshness projection for collection-valued registered inputs instead of hashing their raw container; cover K011 and the sibling K012 case; add generalized regressions proving irrelevant metadata/order perturbations do not stale the obligation while materially decision-changing status changes still do; keep exact subject, authority, prerequisites, constraints, completion and mutation bindings unchanged.
