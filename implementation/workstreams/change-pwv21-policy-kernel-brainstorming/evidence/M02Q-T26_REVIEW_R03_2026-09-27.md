## M02Q-T26-F02 — current Result exact identity may drift from the proved historical Result

Surface: correctness / compatibility.

T26 acceptance requires current Result bytes **and identity** to still match the proved historical source. PW exact Result identity is `repository@commit:path@blob`. The verifier checks that current and source blobs are equal, but it never requires the current Board's `cards.result.commit` to equal the exact historical `cards.result.commit` read from the source Board.

Independent negative probe on exact product `4ebe6b6a...`:

1. create a valid durable statusless Result and a source Board that lists it DONE with exact Result commit/path/blob;
2. create a later commit that leaves the Result bytes/blob unchanged;
3. change only the current Card Result locator to that later commit;
4. keep the migration proof bound to the original source Board snapshot.

Observed output:

`COMMIT_MISMATCH_ACCEPTED=YES`

The historical source Board Result commit and the current Result commit were different, while the blob was identical, and `verify_legacy_result_migration` accepted the proof. This violates the exact-subject/current-identity acceptance boundary and permits a stale/repointed Result identity to masquerade as the proved legacy Result.

Required bounded correction: require the current exact Result locator to match the historical source Board Result locator identity, including commit/path/blob, and add positive/negative regression coverage for same-blob/different-commit and off-history/current-locator variants.

## M02Q-T26-F03 — ambiguous or semantically invalid source Board can certify legacy Result provenance

Surface: correctness / data_integrity.

The verifier parses the immutable source Board but does not validate enough of the Board identity/Result semantics before using it as provenance. In particular it does not require the source Board's `workstream_id` to equal the proved workstream, does not require the historical `cards.result.class` to be `result`, and selects the first matching Card ID without rejecting duplicate/contradictory Card identities.

Independent negative probes on exact product `4ebe6b6a...` produced:

- `WRONG_SOURCE_WORKSTREAM_ACCEPTED=YES`
- `WRONG_SOURCE_CLASS_ACCEPTED=YES`
- `DUPLICATE_SOURCE_CARD_ACCEPTED=YES`

Each fixture retained an otherwise exact durable statusless Result. A wrong-workstream Board, a non-Result locator class, and an ambiguous duplicate Card identity all passed `verify_legacy_result_migration`.

This violates the Card's requirement that the immutable source Board already durably list the exact Result for that DONE Card and that ambiguous proof fail closed.

Required bounded correction: validate the source Board/workstream/Card/Result provenance slice sufficiently to prove one unambiguous Card identity in the expected workstream with an exact `class = "result"` locator, while preserving legitimate historical Board compatibility. Add stable negatives for wrong workstream, wrong locator class and duplicate Card identity.
