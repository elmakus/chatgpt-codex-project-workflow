## M02Q-T29-F02 — migration proof can misstate its Review attempt identity

Surface: contract / acceptance.

The frozen Card requires a valid proof to **uniquely match the selected DONE Card and exact Review-attempt locator**, and explicitly requires mismatched or duplicate proof data to be rejected. Accepted recovery authority also requires contradictory durable bindings to fail closed rather than be ignored.

The current product leaves one semantic identity gap:

1. `validate_review_acceptance_migration_shape` requires a non-empty `attempt_id`, but it does not require `source_path` to be the exact path for that Card/attempt identity.
2. `validate_board` defines proof uniqueness only as `(card_id, attempt_id)`. It separately requires `source_path/source_commit/source_blob` to match exactly one locator in the owner Card's `review_attempts`, but does not prove that the claimed `attempt_id` is the attempt contained in that exact Review locator.
3. Therefore a Board can carry one valid proof for actual R01 plus a second record with the **same exact R01 source path/commit/blob** but `attempt_id = "R99"`. The two records are not duplicate keys, and both source locators still match exactly one selected Review locator, so Board validation accepts the contradictory pair.
4. At serving time `migration_for_attempt(board, card_id, "R01")` selects only the valid R01 record. `verify_review_acceptance_migration` correctly proves that selected record, while the contradictory R99 record is never read back. The valid proof can therefore authorize the DONE/Close path even though durable Board state contains a mismatched second proof for the same immutable Review.

This is load-bearing rather than optional hardening: the accepted Card requires mismatch/duplicate proof rejection and unique exact Review-attempt binding, while PWV21-REQ-092 requires contradictory durable bindings to fail closed.

The defect class is distinct from the previously closed required-evidence-completeness class: the required tests now exist and pass, but they do not cover or prevent this semantic identity contradiction.

Required bounded correction:

- bind `attempt_id` to the exact source Review identity at proof-shape/Board validation, for example by requiring the canonical explicit Review path for `card_id + attempt_id` (or an equivalent exact immutable readback);
- reject reuse of one exact source Review locator under a different claimed attempt identity;
- add a regression where an otherwise-valid proof is duplicated with the same source Review locator and a different `attempt_id`, and require fail-closed Board validation;
- preserve the valid structured-success migration path, RF004 exact acceptance, T26 statusless legacy compatibility and all T09-T12 consumer bytes.

No other material defect class was found in this full-scope discovery pass.
