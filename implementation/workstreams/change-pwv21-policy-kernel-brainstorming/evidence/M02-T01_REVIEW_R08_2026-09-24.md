## Finding R08-F01 — telemetry key-family bypass violates REQ-027

`tools/obligation_contract.py` rejects only a finite exact set of telemetry property names. The canonical Obligation's open `freshness.material.inputs` object therefore accepts semantically equivalent telemetry keys such as `model_name`, `provider_name`, `worker_uuid`, `session_uuid`, `retry_count`, `worktree_path`, and `paseo_job_id`. The JSON Schema's `telemetry_free_json.propertyNames` guard has the same exact-name limitation.

A payload containing one of those keys can consequently be compiled into the canonical typed Obligation, included in `freshness.material.inputs`, and influence the freshness fingerprint and deterministic `obligation_id`. That contradicts PWV21-REQ-027 ("Provider/model/worker/session/retry/worktree/Paseo telemetry MUST remain outside ... the canonical Obligation/Result contract") and ADR-PWV21-002's non-canonical runtime-telemetry boundary. The existing negative tests cover exact names/case variants but not telemetry key families, so CI GREEN does not cover this bypass.
