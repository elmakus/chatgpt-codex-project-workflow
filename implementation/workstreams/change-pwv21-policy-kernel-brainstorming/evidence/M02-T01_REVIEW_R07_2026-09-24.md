## Blocking findings

### R07-F1 — Typed Execution Result cannot represent the produced immutable result/implementation subject

Accepted authority requires an Execution Result to carry both exact binding back to the obligation/subject and the result status/subject (PWV21-REQ-026; P2 M02 acceptance/Appendix A). The existing V2 Card-result contract also persists an exact immutable **Implementation subject**.

The current M02 result schema exposes only one exact-ref field named `subject`. In `tools/obligation_contract.py`, `reconcile_execution_result()` requires:

`result["subject"] == obligation["subject"]`

The golden Result fixture therefore repeats the pre-execution obligation subject (`implementation/cards/M02-T01.md`) instead of carrying a distinct immutable subject for the produced implementation/result. This makes a conforming typed Result unable to express the exact implementation subject that Main must normalize into the durable Card Result (for example the new implementation commit produced by execution).

This is a contract inconsistency across:
- `schemas/EXECUTION_RESULT.schema.json`
- `tools/obligation_contract.py`
- `tests/fixtures/execution_contracts/result-v1.json`
- `workflow/EXECUTION_CONTRACTS.md`
- the preserved V2 `templates/CARD_RESULT.md` / `workflow/EXECUTION.md` semantic result contract.

Required correction: preserve exact original obligation-subject binding while adding an independently exact immutable result/implementation subject to the typed Result, validate it, cover it in golden/schema/reconciliation tests, and keep the existing V2 normalization contract intact.

### R07-F2 — Required negative acceptance coverage is incomplete

Accepted P2 assigns explicit M02 verification for:
- PWV21-REQ-021: authority-altering transport payloads are rejected;
- PWV21-REQ-022: summary-only authority bundles are rejected;

In particular, there is no direct-mutation payload/path rejection test, and no explicit post-resolution authority-bundle tampering or summary-only-substitution test.

Required correction: add focused negative tests against the public typed contract/validation seams, without expanding M02 scope or introducing M03+ behavior.
