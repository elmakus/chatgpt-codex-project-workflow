## Must preserve
- plugin namespace remains `pw`; Skill name is `project_workflow_v2`; accepted invocation is `$pw:project_workflow_v2`;
- plugin directly packages the same canonical `workflow/` tree; Skill, SessionStart hook and metadata remain locator/bootstrap surfaces only;
- ordinary Codex operation reads bundled local workflow authority and does not fetch remote workflow policy or reconstruct it from memory;
- missing/malformed installed root/router fails closed;
- no duplicate V1/V2 `pw` activation or ambiguous semantic source;
- runtime startup/resume/compaction support does not create canonical runtime identity or a V2 Context Health lifecycle;
- project-local provisioning/pinning remains outside V2 under `newproject-skill`.

## Outcome
A thin installable Codex package exposes the common V2 semantics through the accepted `pw` namespace without maintaining a second semantic implementation.

## Included scope
- plugin manifest/package layout;
- `project_workflow_v2` Skill bootstrap;
- SessionStart/root-location hook/bootstrap where required;
- direct canonical `workflow/` packaging;
- package/path-containment, missing-root/router, trust/startup/resume/compaction and source-ambiguity tests.

## Excluded scope
- external project provisioning;
- semantic update live readback (T03);
- real installed-product qualification (T04);
- migration/adoption/cutover.

## Acceptance
- installed package contains the canonical workflow surface directly;
- exact `$pw:project_workflow_v2` entry resolves through bundled local authority;
- malformed/missing root/router fails closed;
- Skill/hook/metadata contain no copied workflow semantics;
- deterministic tests prevent duplicate-source activation and path escape.
