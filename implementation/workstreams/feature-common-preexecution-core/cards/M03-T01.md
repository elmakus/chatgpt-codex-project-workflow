## Must preserve

- Card contract is stable authority; mutable execution/review/result state remains in the selected workstream state owner.
- READY depends on exact authority/prerequisites and testability, never on whether a runtime worker currently exists.
- Materialize currently knowable useful Cards; preserve predecessor-dependent JIT triggers instead of placeholders.
- L1/L2 may refine only not-yet-started work inside accepted authority; strategy routes to Planning, accepted product/global intent to Definition, missing facts to Research.
- Separate technical-contract/OpenSpec remains selective/JIT; a precise Card alone is sufficient for simple work.
- Launch refresh must re-read exact current state/authority/dependencies/results before implementation.
- No runtime role catalog, model preference, worker-adapter API or persisted invocation schema may enter Project Workflow state.
- Pi research is compatibility evidence only; Codex delivery/acceptance remains accepted and unchanged.

## Dependencies

- M02 checkpoint GREEN and integrated.
- Pi pre-execution Research reconciliation applied/consumed with no replan.

## Outcome

The V2 common state/contracts can represent bounded executable Cards, READY/launch-refresh legality and JIT refinement/escalation without importing runtime-specific orchestration schema.

## Included scope

- common Task Card / execution-prep contract;
- minimal structured state needed for Card readiness/dependencies/result/review routing;
- JIT refinement/escalation semantics for not-yet-started Cards;
- selective technical-contract/OpenSpec trigger semantics without mandatory duplicate artifacts;
- production parser/router fixtures for READY independence, stale launch prerequisites, simple Card-only path and contract-heavy trigger path.

## Excluded scope

- actual delegated worker execution/result reconciliation (T02);
- common independent review lifecycle (T03);
- recovery/RED classification (T04);
- runtime-specific Pi or Codex adapter implementation;
- M04 integration/Close semantics.

## Acceptance

- a precise Card can become READY solely from durable authority/prerequisites;
- stale/missing dependency or authority state fails closed before launch;
- simple Card requires no second technical contract;
- a materially contract-heavy case can select the optional technical-contract path without changing strategic authority;
- bounded L1/L2 refinement is distinct from Planning/Definition/Research escalation;
- runtime/model/session/worker identities remain prohibited from canonical state.

## Required verification

- production state/router tests for READY, stale launch, JIT refinement/escalation and selective technical contract;
- A11/A12 foundations for M03.P1;
- `sh scripts/test.sh`;
- exact GitHub readback of target commit/changed surface.
