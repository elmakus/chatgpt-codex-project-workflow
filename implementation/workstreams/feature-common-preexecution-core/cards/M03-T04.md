# M03-T04 — Execution/review recovery and deterministic continuation

Milestone: `M03 — JIT execution, delegated results and common independent review`
Target implementation: `elmakus/project_workflow_v2@feat/pwv2-m03-execution-review`
Depends on: M03-T03
Review requirement: none (covered by cumulative M03 acceptance/review in M03-T05)

## Authority

- `PWV2-P1` M03.P4.
- `requirements/PROJECT_WORKFLOW_V2.md` R1: PWV2-REQ-026, 031, 034..037, 051, 067..071.
- ADR-PWV2-004, ADR-PWV2-005 and ADR-PWV2-006.
- accepted M03-T01..T03 results/evidence.

## Must preserve

- durable completed result is reconciled before any replay after runtime/session loss;
- exact current result/review subject is rechecked before terminal finalization;
- recovery never requires worker/session/model IDs as canonical state;
- RED classification routes bounded correction, Planning, Definition, Research or a real human/runtime blocker according to durable authority;
- ordinary role changes, GREEN/RED verdicts and correction return are not user stops;
- blockers/evidence remain proportional and durable enough for exact recovery.

## Dependencies

- M03-T03 done.

## Outcome

The common router/state contracts can recover interrupted execution/review deterministically, avoid replay of already-durable work and classify RED/blockers into the correct owning route.

## Included scope

- durable-result-before-replay recovery;
- post-review exact-result finalization check;
- RED corrective-route classification;
- Research handoff/return pointers needed by execution resolution;
- proportional blocker/evidence checkpoint semantics;
- route-combination and crash-point fixtures.

## Excluded scope

- M04 moving-target integration, external-effect retry/readback and terminal source-branch recovery;
- deployment/cutover;
- runtime-specific crash supervisor.

## Acceptance

- worker/session disappearance after durable accepted result does not replay implementation;
- stale/different result cannot be finalized under an older GREEN review subject;
- bounded RED correction continues deterministically; plan/Definition/Research/user-stop classifications are distinct;
- Research return is once-only and cannot create a null-pointer/replay gap;
- no runtime telemetry becomes required for recovery.

## Required verification

- A05/A07 recovery fixtures plus route combinations;
- duplicate-result/stale-subject/blocked-state negatives;
- `sh scripts/test.sh`;
- exact GitHub readback.
