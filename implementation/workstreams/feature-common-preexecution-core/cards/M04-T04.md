## Must preserve
- fork-version logic loads only for a durably declared downstream fork-release operation;
- lineage uses accepted upstream repo/tag/SHA, baseline-local numeric private.N, canonical cross-baseline numeric ordering and immutable historical releases;
- optional native latest alias points to the same accepted stable artifact; never synthesize vlatest;
- quality/acceptance remains separate from lineage/version ordering;
- no automatic upstream sync, tag, release or deployment authorization;
- deployment/live-write status alone creates no human gate; an explicit accepted authorization boundary still does;
- true end of approved scope reports durable completion and stops without inventing follow-up work.

## Outcome
The optional fork-publication module is precise, trigger-only and non-authorizing, while Close has explicit true-end-of-scope behavior.

## Included scope
- trigger-only fork lineage module/contract;
- deterministic version-lineage fixtures;
- router/Close end-of-approved-scope semantics.

## Excluded scope
- performing an actual tag/release/deployment;
- M05 delivery/plugin behavior;
- automatic upstream synchronization.

## Acceptance
- ordinary non-fork close never loads fork lineage;
- numeric lanes/order and immutable-history cases are deterministic;
- no synthetic vlatest or implicit release authorization is introduced;
- end-of-scope is a real stop only after durable completion, not a prompt for invented work.

- end-of-scope routing fixture;
- sh scripts/test.sh;
