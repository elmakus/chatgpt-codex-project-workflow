### Must preserve

- Canonical release identity remains `vX.Y.Z-private.N`.
- Baseline-local next-release selection remains numeric `max(N)+1` inside the accepted baseline lane only.
- Cross-baseline current/update selection is a distinct operation over exact canonical private releases.
- Cross-baseline order is numeric `(X, Y, Z, N)`; generic SemVer is not the canonical fork-channel resolver.
- Upstream-only, legacy upstream-looking, malformed and other non-canonical tags are excluded.
- `latest` is optional native moving-alias/channel metadata only, never canonical release identity.
- When used, `latest` points to the newest accepted stable canonical fork release according to project release-quality policy.
- Immutable/versioned references remain available and alias/canonical references identify the same released artifact/content at publication time.
- No synthetic canonical Git release/tag such as `vlatest`.
- `private.N` remains independent from release quality/prerelease metadata.
- Publication authorization/provenance/history rules remain unchanged.
- Downstream repository adoption remains outside this workstream.

## Acceptance

1. OpenSpec is reconciled for M02 and remains inside FRV R2 / ADR-FRV-001.
2. The common contract explicitly distinguishes baseline-local next-release selection from cross-baseline fork-channel selection.
3. Exact canonical private tags are parsed independently of generic SemVer and ordered numerically by `(X, Y, Z, N)`.
4. Upstream-only, legacy, malformed and other non-canonical tags are excluded from channel candidates.
5. Tests prove `private.10 > private.4`, cross-baseline ordering, and that upstream-only `v1.1.18` cannot outrank canonical `v1.1.18-private.4` because it is not a candidate.
6. `latest` is optional native channel metadata, selects only the newest accepted stable canonical fork release under project quality policy, preserves immutable references and exact artifact/content identity, and never creates canonical `vlatest`.
7. README remains concise and points detailed semantics to the common contract.
8. Publication surfaces still reference the one common contract and do not copy the resolver.
9. Focused FRV regression checks and relevant repository-wide tests are GREEN.
10. No downstream/runtime/deployment scope expansion is introduced.
