## Must preserve

- Existing legacy/default single-workstream projects remain valid without forced migration.
- Root `implementation/TASK_BOARD.yaml` remains exclusively the legacy/default state context when that context is selected.
- Branch-isolated workstreams retain isolated durable state and may reuse local milestone IDs without collisions.
- No mutable global workstream registry is introduced.
- Historical completed legacy evidence/handoffs are not rewritten solely for cosmetic consistency.
- Active workstream manifest ↔ Task Board identity remains exact and fail-closed.
- Review independence and integration refresh semantics remain unchanged.

## Outcome

The workflow has one canonical, collision-free rule for branch-isolated terminal state and handoffs, allows recovery after source-branch deletion, and defines a bounded migration path for a pre-workstream branch that used root Task Board/handoff paths.

## Acceptance

1. Branch-isolated cumulative milestone handoffs have a canonical workstream-namespaced path and two independent workstreams may both own `M01` without filename collision.
2. Root `project-handoffs/MXX_HANDOFF.md` and `PROJECT.md -> Latest cumulative handoff` are explicitly legacy/default context; branch-isolated close does not update that project-global pointer.
3. A successfully integrated branch-isolated workstream leaves its terminal manifest, selected Task Board, workstream-owned cards/evidence/handoffs and required recovery pointers on the final integration target.
4. Actual integration result is reconciled in a closure-only target-side state transition when necessary; source branch deletion is allowed only after target readback proves the terminal durable package exists and no unresolved workstream obligation remains.
5. Terminal recovery after source-branch deletion is explicitly supported without weakening active-state manifest ↔ Task Board binding. Original workstream branch remains provenance; terminal recovery may use the integrated target copy when manifest status/result prove final integration.
6. A legacy long-lived branch that mutated root `implementation/TASK_BOARD.yaml` is migrated only at a GREEN/safe boundary: branch-specific live/terminal state is namespaced, branch-only cards/evidence/handoffs are moved or copied into the workstream namespace with pointers reconciled, and the root default board / project-global latest-handoff pointer are restored to the integration-target version before merge unless that default context is explicitly in scope.
7. Shared historical root artifacts that already exist on the target may remain referenced in place; migration does not duplicate/rewrite them solely to satisfy the new layout.
8. Workstream-specific terminal artifacts remain durable history after branch deletion unless a later explicit archival policy is added.
9. Static coherence checks show no active ChatGPT-only module/template still requires global handoff naming for branch-isolated workstreams or says terminal recovery requires the source branch to continue existing.
