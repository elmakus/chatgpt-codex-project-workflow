### Must preserve

- Canonical downstream release identity is `v<upstream-version>-private.<N>`.
- The upstream component is the exact accepted upstream baseline and never advances for fork-local work.
- Release provenance requires exact upstream repository, tag/version, and commit SHA.
- Legacy upstream-looking fork tags/releases remain immutable and are excluded from the canonical private counter.
- First canonical release on a baseline with no private lane is `private.1`; otherwise use numeric `max(N)+1` within that exact baseline only.
- An accepted upstream-baseline change resets the private counter to `1`.
- Generic highest-SemVer across upstream, legacy, and private tag classes is not a valid resolver.
- The `private` suffix is lineage metadata; GitHub `prerelease` remains an independent quality choice.
- One policy-neutral semantic source owns the algorithm; policy-local publication modules only load/apply it.
- Existing publication/review/authorization/signing/checksum/live-write rules remain unchanged.

### Must not / rationale that must travel

- Do not rewrite, delete, retag, or otherwise normalize historical downstream releases.
- Do not define or imply an automatic upstream-sync policy.
- Do not modify the repo-local `.github/workflows/auto-patch-tag.yml` merely because it increments this independent repository's own SemVer tags; FRV applies to downstream-fork release selection.
- Do not duplicate the lineage algorithm in ChatGPT-only, Codex-only, or legacy/shared publication modules.
- Do not treat the OpenSpec as new strategic authority; it must stay inside FRV R1 / ADR-FRV-001.
