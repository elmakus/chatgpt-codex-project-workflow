### Must preserve

- M01 selected-workstream resolution and manifest ↔ Task Board binding occur before branch-isolated mutable execution/review/Research state is interpreted.
- The legacy/default `implementation/TASK_BOARD.yaml` path remains valid without migration.
- Exactly one Card may be `in_progress` per selected workstream Task Board; unrelated workstreams may progress independently.
- M02 Intake remains the owner of new-workstream discovery, identity, independent-vs-stacked base classification and parent/base selection.
- Parent selection is justified only by genuine parent-only dependency, never file overlap, convenience or avoidance of future reconciliation.
- M03 branch-local execution/review/recovery, micro-fix semantics and manifest-owned workstream final-integration review remain intact.
- Card/milestone review lifecycle stays Task-Board-owned; workstream final-integration review stays manifest-owned.
- Behavioral issue/feature integration retains at least a RECOMMENDED fresh independent review gate unless exact stronger GREEN coverage proves the identical immutable integrated subject and whole acceptance surface.
- Remote-only GitHub execution does not require a local worktree; filesystem isolation is required when multiple workstreams actively mutate the same local clone/storage.
- Review invalidation is exact-subject based: target movement alone does not invalidate a verdict when reconciliation leaves the exact covered integrated subject unchanged.
- No mixed/Codex/legacy parallel-lane, capability-routing or scheduler semantics enter `chatgpt_only`.

### Must not / rationale that must travel

- Do not equate branch isolation with filesystem isolation for concurrent local execution.
- Do not let a stacked child integrate to main/default as an independent branch while it still requires parent-only commits.
- Do not treat overlapping files alone as a dependency or blocker.
- Do not invalidate review merely because the integration target moved; invalidate/re-freeze only when the exact covered subject materially changes.
- Do not auto-resolve semantic conflicts by changing accepted product/system authority.
- Do not introduce a global workstream scheduler/registry or repository-wide migration.
- Do not implement M05 user-facing handoff/template/migration/E2E closure beyond preserving the contracts M05 will consume.

## Dependencies

- `M03-T01` GREEN and done at the accepted M03 checkpoint.
- Accepted M01 branch/parent metadata model and M02 base-selection semantics remain in force.

## Outcome

ChatGPT-only defines safe local filesystem concurrency, explicit stacked-child integration constraints and a deterministic pre-integration refresh gate that reconciles target drift without weakening exact-subject independent review semantics.

## Scope

### Included

- update `workflow/chatgpt_only/REPOSITORY.md` to distinguish branch isolation from local filesystem isolation and require separate worktrees/equivalent isolated checkouts for concurrently active local workstreams;
- extend `workflow/chatgpt_only/WORKSTREAMS.md` with explicit stacked dependency semantics, legal child integration paths and cross-workstream conflict rules;
- update `workflow/chatgpt_only/CLOSE.md` so branch-isolated workstream finalization runs an integration refresh gate before final integration/publication;
- define current-target comparison and bounded rebase/merge/retarget/reconciliation choices inside accepted authority;
- define affected-verification reruns after refresh and exact review-subject preservation versus invalidation/re-freeze;
- define parent-integrated transition for stacked children and forbid direct child-to-main integration while parent-only commits remain required;
- update `workflow/chatgpt_only/WORKSTREAM_TEMPLATE.yaml` only if needed to make stacked dependency relation/reconciliation state recoverable without duplicating Task Board Card/milestone state;
- preserve Intake ownership of initial parent/base selection while making M04 integration semantics consumable after that selection;
- define textual versus material semantic conflict handling, with blocking only for real dependency/incompatible authority/unresolved semantic or integration conflict.

### Excluded

- M05 fresh-handoff UX, broad templates/docs migration and full regression/E2E closure;
- changes to mixed, Codex or legacy policy namespaces;
- automatic product/architecture decision-making during conflict resolution;
- a global scheduler/lock service;
- repository-wide migration of existing single-workstream projects;
- material implementation of issue/feature Intake or micro-fix behavior already accepted in M02/M03 except narrowly required references to the new M04 integration contract.

## Acceptance

- concurrent local execution of two workstreams requires separate worktrees/equivalent isolated checkouts while remote-only GitHub operations remain exempt from local-worktree requirements;
- an independent workstream may integrate to its target even while another unrelated feature workstream remains active;
- a stacked workstream is durably distinguishable from an independent one and cannot integrate to main/default while parent-only commits remain required;
- after parent integration, a stacked child refreshes/rebases/retargets/reconciles against the resulting target before final integration;
- every branch-isolated workstream compares its frozen/validated state with the current integration target before final integration;
- material target drift triggers bounded reconciliation plus only affected verification;
- a prior independent review remains valid only when the exact immutable integrated subject and covered acceptance surface remain unchanged; behavioral reconciliation changes create a new frozen exact subject and fresh independent review gate;
- file overlap alone is not a blocker; real dependency, incompatible authority, unresolved semantic conflict or unreconcilable integration conflict is;
- cross-workstream integration checks both textual conflicts and material semantic conflicts;
- legacy/default single-workstream behavior remains legal and no foreign-policy semantics are imported.

## Required tests / checks

- static/coherence audit across changed active `chatgpt_only` contracts for consistent worktree/stacked/refresh terminology and ownership;
- scenario E trace: two local active workstreams → separate worktrees/equivalent checkouts; remote-only operations remain legal without local worktree;
- scenario B trace: child based on parent-only state → parent metadata/dependency → no direct independent child-to-main integration → parent integrates → child refresh/reconcile → legal final integration;
- scenario A trace: independent fix integrates while unrelated feature remains active; feature later refreshes against moved target rather than being globally blocked;
- unchanged-subject refresh trace: target moved, reconciliation leaves exact covered integrated subject unchanged → affected verification rerun as needed, prior exact review coverage may remain valid;
- changed-subject refresh trace: reconciliation changes behavioral integrated subject → prior verdict no longer covers it → freeze new exact subject and require fresh independent review;
- overlap/conflict trace: overlapping files alone do not block; textual/material semantic conflict that cannot be resolved inside accepted authority blocks/strategically reroutes only the affected workstream;
- legacy/default regression trace and foreign-policy boundary audit;
- `git diff --check` equivalent inspection of the exact M04 implementation subject available through the execution runtime.
