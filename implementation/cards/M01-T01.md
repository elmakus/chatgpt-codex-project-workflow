# M01-T01 — Workstream state model and routing foundation

- Milestone: `M01`

> This file is a stable Task Card contract. Mutable execution/review/result state lives only in the canonical Task Board selected by the ChatGPT-only workstream resolver.

## Authority slice

- Master Plan / milestone contract: `planning/CHATGPT_ONLY_MULTI_WORKSTREAM_MASTER_PLAN.md#M01--workstream-state-model-and-routing-foundation`
- Requirements: `requirements/CHATGPT_ONLY_MULTI_WORKSTREAM_INTAKE.md` — R1, R2, R3, R12, R14, R15
- Accepted decisions: `decisions/ADR_CHATGPT_ONLY_BRANCH_ISOLATED_WORKSTREAMS.md`
- Relevant OpenSpec: `none` — the workflow Markdown/YAML contracts are themselves the canonical behavior/state specification for this documentation-first repository change; avoid a duplicate spec layer unless implementation exposes a separate machine-consumed contract.
- Accepted dependency results: `planning/reviews/MW-R1.md` (GREEN independent plan review)

### Must preserve

- Exactly one Card may be `in_progress` per selected workstream Task Board.
- Independent workstreams use distinct branches and distinct mutable workstream state.
- Existing projects with only `implementation/TASK_BOARD.yaml` remain valid without migration.
- Resolve the exact branch/workstream before loading implementation/review/recovery state.
- A workstream manifest is routing/workstream-lifecycle metadata; Card/milestone execution/review state remains canonical only in the selected Task Board.
- No mutable repository-global workstream registry is required for correctness.
- Do not import mixed/Codex/legacy parallel-lane semantics into `chatgpt_only`.
- Preserve current fresh-review, Research-return and user-owned Definition-promotion semantics except for the minimum path-selection generalization required by selected-workstream state.

### Must not / rationale that must travel

- Do not reinterpret multi-workstream support as parallel Cards inside one workstream.
- Do not require migration or movement of an existing active default Task Board.
- Do not create a second canonical copy of Card/milestone/review state in the workstream manifest.
- Policy-neutral common wording may be generalized only in a way that remains valid for non-`chatgpt_only` routes.

## Dependencies

- none

## Outcome

Current workflow can deterministically resolve either the legacy/default `implementation/TASK_BOARD.yaml` or one exact branch-isolated workstream manifest plus its canonical Task Board before implementation/review/recovery routing.

## Scope

### Included

- add `workflow/chatgpt_only/WORKSTREAMS.md`;
- add a branch-isolated workstream manifest template;
- add a workstream-local Task Board template or an equivalent parameterized policy-local template without weakening serial semantics;
- update ChatGPT-only state/router/repository contracts for selected-workstream resolution and legacy fallback;
- update the policy dispatcher/common authority/bootstrap wording that must be generalized for the M01 acceptance state to be coherent;
- update policy-local Task Card/template wording where a hard-coded default Task Board path would make selected-workstream state contradictory;
- add focused static/coherence checks when practical for M01 invariants.

### Excluded

- `#issue` / `#feature` intake behavior (M02);
- micro-fix execution path and full workstream review/recovery adaptation (M03);
- worktree/stacked/integration-refresh semantics beyond fields required by the manifest schema (M04);
- final UX/docs/migration/E2E closure (M05).

## Acceptance

- a legacy project with only `implementation/TASK_BOARD.yaml` still resolves exactly as before;
- a selected branch-isolated manifest resolves one exact workstream Task Board before implementation/review/recovery state is read;
- two different workstream Task Boards may each contain one `in_progress` Card without either being invalid merely because the other exists;
- two `in_progress` Cards in the same selected workstream remain invalid;
- manifest and Task Board ownership are non-circular and do not duplicate Card/milestone review state;
- no global mutable workstream registry is introduced;
- no foreign-policy parallel/executor semantics are imported.

## Required tests / checks

- grep/static audit of active `chatgpt_only` + policy-neutral bootstrap/state wording for contradictory repository-global Task Board/seriality claims relevant to M01;
- logical recovery trace for legacy/default Task Board;
- logical recovery trace for an exact selected workstream manifest + Task Board;
- logical invalid-state trace for two `in_progress` Cards in one workstream;
- logical valid-state trace for one `in_progress` Card in each of two independent workstreams;
- verify non-`chatgpt_only` routes remain semantically valid after any common wording generalization.
