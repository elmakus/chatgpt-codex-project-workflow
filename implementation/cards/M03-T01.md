# M03-T01 — Micro-fix and branch-local execution/review/recovery semantics

- Milestone: `M03`

> This file is a stable Task Card contract. Mutable execution/review/result state lives only in the canonical Task Board selected by the ChatGPT-only workstream resolver.

## Authority slice

- Master Plan / milestone contract: `planning/CHATGPT_ONLY_MULTI_WORKSTREAM_MASTER_PLAN.md#M03--micro-fix-execution-review-and-recovery-semantics`
- Requirements: `requirements/CHATGPT_ONLY_MULTI_WORKSTREAM_INTAKE.md` — R1, R2, R3, R6, R7, R12, R14, R15 plus acceptance scenarios C and F
- Accepted decisions: `decisions/ADR_CHATGPT_ONLY_BRANCH_ISOLATED_WORKSTREAMS.md`
- Relevant OpenSpec: `none` — JIT classification complete: this milestone changes the repository's canonical workflow/state contracts directly in Markdown/YAML; a second OpenSpec layer would duplicate the same persistent state/reconciliation contract rather than reduce ambiguity.
- Accepted dependency results: `project-handoffs/M02_HANDOFF.md`; `implementation/evidence/M02-acceptance.md` (GREEN); `implementation/evidence/M02-T01-review-02.md` (GREEN)

### Must preserve

- M01 selected-workstream resolution and manifest ↔ Task Board binding occur before branch-isolated Card/milestone/review/Research state is interpreted.
- The legacy/default `implementation/TASK_BOARD.yaml` path remains valid and recoverable without migration.
- Exactly one Card may be `in_progress` per selected Task Board; unrelated workstreams may progress independently.
- M02 intake identity, pre-creation diagnosis/discovery, independent-vs-stacked base classification and downstream materialization remain intact.
- A micro-fix may omit a full Master Plan/milestone decomposition only when all R6 qualification criteria are proven; it never omits durable scope/acceptance, implementation evidence, exact subject freeze or required fresh review.
- Behavioral issue/feature workstreams have at least a RECOMMENDED workstream-level final integration review unless an existing stronger exact-subject review already covers the integrated subject.
- Card/milestone review state remains canonical only in the selected Task Board; workstream manifest review fields are reserved for the distinct final-integration gate and must not mirror Card/milestone review state.
- Implementation/recovery Research pointers belong only to the selected Task Board and must never be resolved through another workstream's Task Board.
- RED review correction remains attached to the exact affected selected workstream and does not create or mutate a parallel lane.
- Same-branch/same-manifest recovery resumes the same durable active obligation rather than creating a second workstream.
- No mixed/Codex/legacy parallel-lane, executor-routing or scheduler semantics enter `chatgpt_only`.

### Must not / rationale that must travel

- Do not make a micro-fix a synonym for “skip planning controls”; qualification must be explicit and false/uncertain qualification must route to the smallest normal downstream role.
- Do not create a repository-global micro-fix or review registry.
- Do not duplicate workstream final-integration review into Card/milestone review fields or vice versa.
- Do not inspect unrelated workstream Task Boards during normal execution/review/recovery merely to discover possible work.
- Do not implement M04 worktree isolation, stacked rebase/retarget or integration-target refresh mechanics beyond preserving the metadata/gates they will consume.
- Do not implement M05 handoff UX, migration/E2E closure or broad documentation cleanup.
- Do not change accepted requirements/architecture or silently migrate this project's legacy/default Task Board.

## Dependencies

- `M02-T01` GREEN and done at the accepted M02 checkpoint.
- M01 workstream state model remains the accepted selected-state foundation.

## Outcome

ChatGPT-only can execute, review and recover one exact selected workstream without consulting unrelated mutable state, while bounded issue work can take a durable micro-fix path that skips heavyweight planning but preserves verification and fresh independent review.

## Scope

### Included

- define the canonical micro-fix durable contract and qualification/materialization semantics after M02 Intake selects `path: micro_fix`;
- define how a micro-fix initializes a selected workstream Task Board without requiring a Master Plan/milestone decomposition while still using one bounded executable Card/fix contract as the live execution unit;
- update `workflow/chatgpt_only/ROUTER.md`, `EXECUTION_PREP.md`, `EXECUTION.md`, `REVIEW.md`, `STATE.md`, `RECOVERY.md` and `RESEARCH.md` where needed so branch-isolated execution/review/recovery always resolves and stays inside the selected workstream state;
- update `workflow/chatgpt_only/WORKSTREAMS.md`, workstream templates and/or task-board template only where needed to make micro-fix and final-integration-review ownership/recovery unambiguous;
- define workstream-level final integration review activation for behavioral issue/feature workstreams, including exact subject/evidence binding and fresh-chat independence;
- preserve existing Card/milestone review mechanics inside the selected Task Board;
- define RED correction/research-return behavior so the selected workstream remains the sole affected mutable execution context;
- define same-branch fresh-session recovery of active execution/review/Research obligations without creating a parallel workstream lane.

### Excluded

- local worktree/equivalent checkout enforcement (M04);
- stacked parent integration, rebase/retarget and integration-target refresh mechanics (M04);
- final merge/publication semantics beyond establishing the M03 final-integration review gate consumed later by M04/M05;
- final user-facing handoff template/migration/E2E closure (M05);
- changes to mixed, Codex or legacy policy namespaces.

## Acceptance

- a Tint2-style issue satisfying every R6 criterion can materialize one durable micro-fix/fix contract plus selected workstream Task Board state without a full Master Plan/milestone decomposition;
- the micro-fix execution unit has explicit authority/scope/acceptance/tests, produces durable implementation evidence, freezes an exact immutable subject and reaches a real fresh independent review boundary before integration when behavior/config/code changes;
- when R6 qualification is false or uncertain, the workflow routes to the smallest normal Research/Definition/Planning/Execution-Prep path rather than forcing micro-fix;
- normal branch-isolated Execution Prep, Execution, Review, Recovery and implementation-owned Research read/write only the manifest-selected Task Board after identity validation;
- recovery of a second chat on the same branch/manifest resumes the same pending review, Research obligation, RED correction, in-progress Card or READY work as appropriate and never creates a second lane;
- RED correction and any Research handoff remain scoped to the exact affected workstream;
- Card/milestone review lifecycle remains unchanged inside a workstream;
- behavioral issue/feature workstreams expose a distinct workstream-level final integration review gate of at least RECOMMENDED unless a stronger existing exact-subject review is proven to cover the integrated subject;
- workstream manifest final-review metadata never becomes a mirror of selected Task Board Card/milestone review state;
- legacy/default single-workstream execution/review/recovery remains legal and semantically unchanged;
- no M04 integration-refresh/worktree behavior or foreign-policy orchestration semantics are imported.
