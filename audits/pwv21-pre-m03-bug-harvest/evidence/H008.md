## Claim under test

A newly authored first terminal RED review can omit the PWv2.1 review/evidence fields and be accepted as legacy merely because it has legacy schema shape, even though the compatibility exception is intended for genuinely historical pre-PWv2.1 records.

## Expected semantics

PWV21-REQ-133 and the M02R-T03 acceptance surface require a new PWv2.1 RED discovery attempt to carry materially load-bearing evidence. Genuine pre-PWv2.1 review history may need compatibility treatment, but that exemption must be based on durable historicity/provenance rather than on an actor choosing to omit the new fields.

## Observed historical-subject behavior

At implementation subject `180cc0af3a9b56c8c2808827bf5548b8ae040608`:

1. `validate_review()` treats `review_kind` as the discriminator for the PWv2.1 shape. If `review_kind` is absent and no other PWv2.1-only fields are present, the record remains valid under the legacy shape.
2. Load-bearing RED requirements such as complete `material_finding_ids` and `finding_severity` are enforced only inside the explicit-PWv2.1 branch.
3. `validate_review_history()` initializes `legacy_prefix = True`.
4. An attempt without `review_kind` is accepted while that prefix is still true, provided it is terminal (`green` or `red`).
5. The first attempt is therefore sufficient to establish its own “legacy” treatment purely by schema shape. There is no durable timestamp, predecessor state, immutable cutoff subject, migration ledger, or other provenance proving that the attempt actually predates the PWv2.1 evidence contract.

A freshly authored R01 with `verdict = "red"`, terminal `evidence_path`, exact subject/acceptance/independence fields, and no `review_kind`, `material_finding_ids`, or `finding_severity` is consequently accepted as an initial legacy-prefix RED.

This reproduces the semantic counterexample identified independently by S2-F1 and S4-F3.

## Technical verdict

CONFIRMED_MATERIAL

## Why

The compatibility boundary confuses representation age with record age. Absence of new fields proves only that a record has old schema shape; it does not prove that the record is historical.

That distinction is load-bearing because a new RED can trigger correction/recovery authority while bypassing the evidence classification that PWv2.1 requires for a newly created RED. Backward compatibility for genuinely historical records is not itself the defect.

## Smallest likely defect boundary

The smallest defect boundary is the legacy-compatibility admission predicate in review-history validation. The validator needs a durable, non-self-asserted way to distinguish genuinely migrated historical attempts from newly authored records. The evidence-gated semantics for explicit PWv2.1 RED should remain unchanged.

## Useful regression-test shape

Construct one exact current review subject and validate two otherwise equivalent first RED attempts:

1. A genuinely migrated historical attempt with durable compatibility provenance -> accepted under the documented compatibility rule.
2. A newly authored no-`review_kind` R01 with the same legacy-shaped fields -> rejected/recovery.
3. A newly authored explicit PWv2.1 RED lacking `material_finding_ids` -> rejected.
4. A newly authored explicit PWv2.1 RED with material IDs but incomplete/missing `finding_severity` -> rejected.
5. A complete explicit PWv2.1 RED with load-bearing evidence -> accepted.

The regression must prove that old schema shape alone cannot manufacture historical status.
