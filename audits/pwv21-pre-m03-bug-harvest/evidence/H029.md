## Claim under test

A locator can satisfy lexical class/workstream restrictions and then resolve to a different semantic location under host filesystem behavior, while remaining inside the broad project root and therefore passing the reader's final containment check.

## Historical source evidence

Two source audits expose distinct mechanisms sharing that boundary.

S018-F04 uses an in-repository symlink. A declared authority locator such as `workflow/ALIAS.md` passes lexical authority validation, but if the file is a symlink to `../untrusted/ISSUE_TEXT.md`, `Reads._read_path()` follows it. Because the resolved target is still somewhere inside the project root, the read is allowed and the read set records only the declared authority-looking path. That source locally exercised the exact path-resolution logic.

S009-F06 uses Windows separator semantics. A raw Card path with components containing backslashes can pass POSIX lexical checks/prefix checks because `PurePosixPath` does not treat backslash as a separator. Host-native Windows path realization then interprets those backslashes and can normalize into another workstream. That source confirmed the normalization behavior and correctly scoped impact as platform-conditional.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

- `tools/state_contract.py::_safe_relative_path()` parses the raw locator with `PurePosixPath` and rejects only POSIX `.`/`..` parts and absolute paths.
- `validate_locator()` applies class/workstream constraints to the raw string, including prefix checks for Task Cards, results, evidence and reviews.
- `tools/router.py::Reads._read_path()` repeats the POSIX lexical check, then converts the parts to host `Path`, calls `.resolve()`, and verifies only that the resolved target is under the broad project/package root.
- It does not reassert the declared semantic root (for example `workflow/` or the selected workstream's `cards/` directory) after resolution.
- The read set records `owner:raw`, not the resolved semantic source.

Therefore a filesystem alias can cause bytes outside the declared class root to be consumed under a locator that passed class validation.
