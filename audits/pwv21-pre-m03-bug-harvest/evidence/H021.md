## Claim under test

An approved Planning / Plan Review / premium-gate chain derived from Definition R1 can remain authoritative after the current Definition changes to R2 because the production validators and router do not bind Planning's entry subject to the current Definition revision/authority.

## Expected historical acceptance

The Definition-to-Planning lifecycle requires Strategic Planning and its premium/review cycle to derive from the current accepted Definition authority. A material re-entry or changed Definition must not silently reuse the old cycle; stale or contradictory durable state must fail closed or re-enter the required planning gates.

The source class explicitly separates this invariant from any particular textual serialization of `entry_subject`: the material requirement is a durable exact cross-record binding to current Definition authority.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. `tools/state_contract.py::validate_definition()` validates the Definition record internally, including a non-empty `revision`, GREEN completeness and accepted authority locators.
2. `validate_planning()` independently validates a non-empty `entry_subject` and only requires `premium_a_subject == entry_subject`; it does not receive or compare the current Definition record.
3. In `tools/router.py`, the current Definition is loaded and validated, then Planning is loaded and validated separately.
4. The router uses `definition["revision"]` only when no Planning record exists, while later Planning routing uses `planning["entry_subject"]` and the Planning/Plan Review subject chain. There is no comparison between the two.
5. The aggregate's five independent source reproducers therefore use the same minimal state transition: start with a valid approved R1 planning chain, change the current Definition to R2 while leaving Planning/Plan Review/premium state internally unchanged, and observe the router continue into Execution Prep or the live Task Board/Execution instead of invalidating the stale plan.

The current upstream authority can therefore advance without invalidating downstream strategy and premium approvals derived from the previous Definition.

## Technical verdict

CONFIRMED_MATERIAL

## Why

Definition is the current accepted product/requirements authority for Planning. Internal consistency within the old Planning cycle is insufficient once the upstream authority changes.

Without an exact Definition-to-Planning freshness binding, stale strategy, review and premium approvals can continue to authorize implementation after the authority they were derived from has been superseded.

## Smallest relevant implementation boundary

The smallest defect boundary is the Definition -> Planning entry/freshness contract spanning `tools/state_contract.py::validate_definition()`, `validate_planning()`, and the Planning-entry section of `tools/router.py`.

A durable exact key representing the current Definition authority must be compared with the Planning cycle's recorded entry authority before any existing Planning/Plan Review/premium state is reused.
