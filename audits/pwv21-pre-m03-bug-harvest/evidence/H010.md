## Claim under test

A durable evidence reference can be accepted and used as result/review/provenance truth even when the target evidence artifact does not exist.

## Expected canonical semantics

Accepted implementation and review evidence is durable workflow truth. PWV21-REQ-134 additionally requires durable observation provenance. A locator that is syntactically valid but dangling cannot provide durable evidence or durable provenance; the consuming boundary must fail closed when the target cannot be established.

## Observed historical-subject behavior

At PWv2 subject `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. `tools/execution_contract.py::parse_card_result()` requires at least one evidence ref and checks only path shape, workstream-local prefix and `.md` suffix.
2. It does not read or otherwise establish existence of any referenced evidence artifact.
3. The active-result router reads the Result and Task Card, invokes `parse_card_result()`, and can continue into result reconciliation/review routing without dereferencing those evidence refs.
4. The preserved `S001-F02` reproducer uses a valid-looking `implementation/workstreams/sample-workstream/evidence/DOES-NOT-EXIST.md` locator; its shape is accepted although existence is not checked.

At M02R-T03 implementation subject `180cc0af3a9b56c8c2808827bf5548b8ae040608`:

1. Observation provenance validation binds an observation's evidence string to its originating terminal review's `evidence_path`.
2. Matching strings establish provenance relationship but do not establish that the referenced artifact exists.
3. Consequently the S1-F2/S2-F2 vector can use the same nonexistent evidence path in the review and observation, with an observation suffix such as `#O1`, and satisfy provenance binding while the terminal evidence artifact is absent.

These are the same semantic defect family at two evidence-consumption boundaries: locator agreement/shape is treated as sufficient evidence without durable target readback.

## Technical verdict

CONFIRMED_MATERIAL

## Why

The behavior violates the durable-evidence premise used for accepted results, terminal review evidence and observation provenance. A dangling locator is not equivalent to durable evidence, yet these boundaries can consume it as if the proof exists.

The cross-source overlap is material rather than cosmetic because later reconciliation, review and Final semantics can rely on the accepted locator after the underlying proof has disappeared or was never created.

## Smallest likely defect boundary

The smallest defect boundary is the durable-evidence consumption seam: any result/review/provenance locator that carries workflow proof must be resolved and verified at the boundary where that proof is accepted, rather than only syntax-checked or compared as a string.

This audit does not prescribe whether that proof should use project-tree readback, exact Git identity, or another canonical immutable locator form; it only establishes that a dangling target cannot satisfy the durable-evidence contract.

## Useful regression-test shape

1. Start from a valid result/review/provenance fixture whose evidence artifact exists and assert the normal route.
2. Delete only the referenced evidence artifact while leaving the locator unchanged.
3. Assert fail-closed behavior before result reconciliation, terminal review consumption, or Final provenance reconciliation.
4. Repeat with an observation whose locator exactly matches the terminal review `evidence_path` plus an allowed observation suffix; matching strings with a missing target must still fail.
5. Include a positive case proving an actually present durable artifact continues to pass.
