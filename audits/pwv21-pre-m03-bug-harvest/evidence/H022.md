## Claim under test

A downstream Definition can be treated as valid while the durable Brainstorm record for the same exact revision still says `state = "active"`, provided the separate promotion authorization fields are already exact.

## Expected historical acceptance

The historical `workflow/BRAINSTORMING.md` defines an `active -> ready_for_definition -> promoted` lifecycle and says that the exact promoted revision owns continuation into Definition. `workflow/DEFINITION.md` says Definition converts one explicitly promoted exploratory revision and requires the exact promoted Brainstorming subject.

A matching authorization subject alone therefore cannot substitute for the durable promoted lifecycle state.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. `tools/state_contract.py::validate_brainstorm()` accepts `state = "active"` together with `promotion_state = "authorized"` and a matching `promotion_subject`; only `state = "promoted"` implies the reverse requirement.
2. `tools/router.py` loads Brainstorm and Definition and computes the exact `scope_id@revision` subject.
3. The Definition cross-record predicate checks `promotion_state == "authorized"`, matching `promotion_subject`, and matching `definition.source_scope_subject`, but never requires `brainstorm.state == "promoted"`.
4. The source reproducer `repro_router_state_gaps.py::f4_definition_accepts_non_promoted_brainstorm_state` takes a normal GREEN Definition fixture, changes only Brainstorm `state = "promoted"` to `state = "active"`, and expects `route/planning`.

The production predicates therefore admit the exact contradictory lifecycle state described by the source finding.

## Technical verdict

CONFIRMED_MATERIAL

## Why

The durable lifecycle state is part of Brainstorming's authority transition. Allowing Definition while the upstream owner still records the scope as active means downstream authority can exist without the required durable promotion transition.

This is not merely a cosmetic inconsistency: it bypasses the owner state that distinguishes active exploration from a promoted Definition subject.

## Smallest relevant implementation boundary

The smallest boundary is the Brainstorm -> Definition lifecycle binding spanning `tools/state_contract.py::validate_brainstorm()` and the Definition cross-record predicate in `tools/router.py`.

The relevant invariant is that a Definition locator may be consumed only when the exact bound Brainstorm revision is durably in the promoted lifecycle state as well as carrying exact promotion authorization.
