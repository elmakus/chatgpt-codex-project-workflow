## Claim under test

A durable Brainstorming `explicit_user_stop = true` can remain validator-legal while Definition, Planning, or Task Board state exists, and production `select_route()` can return a downstream obligation before the explicit stop is evaluated.

## Expected canonical semantics

`workflow/BRAINSTORMING.md` makes the selected Brainstorm revision the durable owner of the explicit user-stop signal and states `explicit user stop -> real stop`. `workflow/USER_STOP.md` independently lists `explicit user stop` as a real-stop source. `workflow/STATE.md` says `BRAINSTORM.toml` owns both the explicit user stop and the separate Definition-promotion authorization.

No audited canonical contract says that promotion, Definition materialization, Planning, or Task Board materialization implicitly clears `explicit_user_stop`. Promotion authorization therefore does not silently supersede a still-true stop. The tested state carries current durable human authority, not merely a historical Brainstorm record.

## Minimal reproduction

workstream_id = "sample-workstream"

Exact-bound active Definition:

```toml
workstream_id = "sample-workstream"
source_scope_subject = "scope-stop@1"

completeness_audit = "pending"
premium_a = "not_due"
decisions = []

[requirements]
class = "authority"

```

At the original subject, `validate_brainstorm()` accepts the promoted/authorized record because `explicit_user_stop` is independently required only to be boolean; there is no invariant forbidding `true` with `state = "promoted"`. `validate_definition()` accepts the active Definition form. The router cross-binding accepts the pair because promotion state/subject and `definition.source_scope_subject` all match `scope-stop@1`.

Production selector order then enters the `definition is not None` block and returns `route / definition` immediately for `definition["state"] == "active"`. The later Brainstorm branch containing the `explicit_user_stop` check is never reached.

### Variant B — approved Planning plus co-bound active Task Board

The audited production router tests contain a legal chain of promoted Brainstorming, GREEN Definition with A satisfied, approved Planning with B/C satisfied, GREEN Plan Review, and a co-bound valid Task Board whose Card is `in_progress`; that chain routes to `execution`.

Changing only the Brainstorm field from `explicit_user_stop = false` to `true` does not invalidate any Brainstorm, Definition, Planning, Plan Review, or Board predicate. Approved Planning with a Board sets `plan_gate_passed_with_board = True`; the explicit Brainstorm stop is guarded by `if not plan_gate_passed_with_board and brainstorm is not None`, so the stop branch is skipped and the active Card can route to Execution.

The sibling vector is governed by the same precedence defect.

## Why

The canonical contracts require a still-true explicit user stop to be a real human-facing boundary and define no implicit downstream clearance rule. The state contract admits that stop alongside exact downstream state, while the production selector can return downstream Definition/Planning/Board obligations first or structurally skip the stop branch. That is a concrete canonical precedence contradiction.
