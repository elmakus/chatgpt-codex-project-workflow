## Claim under test

The documented Close-to-true-end transition exists as a standalone helper semantic but is not connected to the production selector, so terminal durable state can repeatedly route to Close without a production path that emits the documented `end_of_scope_stop`.

## Historical source evidence

S017-F04 identifies the exact separation: all-DONE state makes `select_route()` return `route/close`, while `close_continuation(approved_scope_durably_complete=True, next_authorized_obligation=False, explicit_authorization_gate_due=False)` separately returns `end_of_scope_stop`. Its preserved reproducer is `repros/repro_findings.py::f04_close_stop_is_disconnected`.

The canonical Router says Close must continue deterministic authorized obligations until durable approved-scope completion and then reach the end-of-scope stop. `workflow/CLOSE.md` assigns the continuation oracle to `tools/close_contract.py`, and true end of scope is not inferred merely from the Card queue.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. `tools/router.py` routes a non-empty Board whose Cards are all DONE directly to `route/close`.
2. There is no `close_continuation` import, invocation, `end_of_scope_stop` branch, or selector input representing durable Close-completion truth.
3. Therefore invoking the production selector again on the same all-DONE durable state produces the same Close route.
4. `tools/close_contract.py::close_continuation()` separately returns:
   - `authorization_stop` for an explicit authorization gate,
   - `end_of_scope_stop` when approved scope is durably complete and no next authorized obligation remains,
   - deterministic continuation/reconciliation otherwise.
5. That helper return type is a string and is tested in isolation; it is not consumed by the selector to build the real stop result that would also load `workflow/USER_STOP.md`.

The documented terminal transition is therefore not reachable through the production selector itself.

## Smallest relevant implementation boundary

The smallest boundary is the composition seam between terminal dispatch in `tools/router.py` / `policy/mechanical_policy.json::PWV21-K012` and `tools/close_contract.py::close_continuation()`. A durable representation/readback of the Close completion state must be sufficient for the production routing path to emit the real stop and load USER_STOP.

## Useful future regression-test shape

1. Start from a valid all-DONE Board; assert the first selector decision routes Close.
2. Persist the canonical durable Close-completion evidence/state required by the design.
3. Re-enter the production routing path and assert it returns `disposition=stop`, `obligation=end_of_scope_stop`, and includes USER_STOP in the read set.

6. Negative control: explicit authorization gate due -> authorization stop, not end-of-scope stop.
