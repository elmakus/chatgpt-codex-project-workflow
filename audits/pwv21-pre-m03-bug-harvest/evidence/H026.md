## Claim under test

The durable JIT lifecycle can fall out of routing/terminal-completeness decisions: a satisfied predecessor-dependent trigger may coexist with all currently materialized Cards DONE and still route to Close, while a consumed trigger may lack proof that its downstream Card was actually materialized.

## Historical authority and source evidence

`workflow/EXECUTION_PREP.md` defines JIT lifecycle as `waiting -> satisfied -> consumed` and states that a satisfied trigger requires the predecessor Card to be DONE with a durable result before downstream materialization. `workflow/CLOSE.md` states that Close may report end of approved scope only when no already-authorized obligation remains; empty/currently terminal Card state is not itself proof of end of scope.

Eight independent source audits clustered the behavior. The repeated concrete vector is one DONE predecessor with a result plus a top-level `satisfied` trigger and no downstream Card. S002, S004, S022, S024, S026 and S027 each describe the selector taking Close despite that durable trigger. S034 additionally demonstrates that `consumed` is accepted without a downstream-card/consumed-by proof.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. `validate_board()` validates JIT records and accepts `satisfied` or `consumed` when the named predecessor is DONE with a result.
2. The trigger does not require an exact downstream Card/materialization binding when marked `consumed`.
3. The production selector does not give ordinary JIT trigger state a routing branch before terminality.
4. With the existing Cards all DONE, the selector reaches its all-terminal path and routes `close`.
5. The historical documentation simultaneously says a satisfied trigger represents predecessor-dependent work whose stable downstream Card is now due to be materialized and that Close cannot infer true completion from an empty/currently terminal Card queue.

The accepted state therefore contains an already-authorized executable obligation that is absent from the selector's terminal decision.
