## Claim under test

SessionStart can positively certify an installed router as canonical even when its workflow semantics have been removed or replaced, provided two expected marker strings survive.

## Historical source evidence

Six independent source audits converged on the same bootstrap boundary. Their minimal reproductions replace a temporary installed `workflow/ROUTER.md` with a two-line or contradictory body that preserves the V2-router heading and the production-selector sentence naming `tools/router.py`.

The real SessionStart hook then emits normal enabled/canonical context rather than the blocking package-error context. Several reports persisted temporary-package repro scripts, including `f5_sessionstart_truncated_router.py`, `repro_session_start_sentinel.py`, `f4_sessionstart_marker_spoof.py`, and `repro_session_start_marker_failopen.py`.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`, `hooks/session-start.py::canonical_router()`:

1. requires `workflow/ROUTER.md` to exist;
2. resolves it and rejects escape outside the installed package root;
3. reads it as UTF-8;
4. declares it valid if the two marker substrings are present.

There is no digest, package-manifest binding, semantic-structure check, release/version match, or other integrity proof for the router bytes. `build_context()` then tells the runtime the V2 package is enabled and names that file as the canonical bundled router.

The historical negative test `test_missing_and_malformed_router_fail_closed` covers a missing file and text `not a V2 router`, so it removes the very markers the implementation trusts. It does not cover semantic destruction with markers preserved.
