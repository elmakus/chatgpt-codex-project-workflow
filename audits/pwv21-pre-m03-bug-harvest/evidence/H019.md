## Why

PWV21-REQ-136's cleanup gate is load-bearing for Final. The validator proves only declaration shape and boolean assertions, not existence or identity of the claimed Git subject, tests/evidence, or independent GREEN review. This permits a cleanup candidate to become non-blocking without the durable proof the acceptance contract requires.

## Smallest relevant implementation boundary

The smallest defect boundary is the cleanup-proof contract around `tools/close_contract.py::validate_cleanup_work()` and the Final cleanup-work consumption path in `verify_final_observation_reconciliation()`.

The boundary needs durable readback/binding for the declared cleanup subject, evidence and independent review, rather than treating their serialized declarations as proof.

## Useful future regression-test shape

1. Nonexistent repository/commit/blob/path tuple with valid 40-hex shapes plus non-empty evidence and `independent_review_green=true` -> reject.
2. Existing cleanup result path but mismatched declared blob -> reject.
3. Existing test/evidence locator whose artifact is absent -> reject.
4. GREEN review declaration without a durable independent review artifact bound to the exact cleanup subject -> reject.
5. Real cleanup subject + real evidence + exact independent GREEN review + matching cleanup-candidate coverage -> accept.
6. Speculative/new-product scope should be derived or verified against authority rather than accepted solely from false caller flags.
