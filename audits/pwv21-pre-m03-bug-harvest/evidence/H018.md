## Claim under test

The authoritative pre-Final observation reconciliation helper can derive its canonical observation history from only the current Task Board locator slice and therefore accept Final while an older durable review attempt still contains an unreconciled observation that the current Board no longer lists.

## Expected historical acceptance

The exact M02R-T03 Card at the historical consumer subject owns PWV21-REQ-133 through PWV21-REQ-136. Its acceptance requires that every non-load-bearing observation remain durable and traceable until reconciled, and that Final Integration cannot complete with any unreconciled open observation.

Its required negative testing explicitly includes rejection of silent observation loss.

The exact R02 result blob names `project_workflow_v2@180cc0af3a9b56c8c2808827bf5548b8ae040608` as its implementation subject.

## Observed historical-subject behavior

At `180cc0af3a9b56c8c2808827bf5548b8ae040608`:

1. `tools/close_contract.py::verify_final_observation_reconciliation_from_board()` reads the current Task Board and selects the requested Card from that one current board snapshot.
2. It obtains canonical review history exclusively from that Card's current `review_attempts` locator array.
3. It reads and validates only the attempt files named by those current locators, then derives the canonical observation set from that resulting list.
4. The helper has no prior-Board/history input and performs no append-only/completeness comparison proving that a previously durable attempt locator was never removed.
5. Consequently, if a previous Board revision listed R01 containing open observation O1, but the current Board is rewritten with `review_attempts = []` while the durable R01 file remains, the helper constructs `attempts = []` and has no O1 to reconcile.
6. The historical repository test `test_board_gate_accepts_proven_empty_history_and_reviewed_cleanup` explicitly constructs a current Board with an empty review-attempt list and expects `observations=[]` to return `final_observation_reconciliation_complete`.

The helper's current snapshot cannot distinguish a truly never-reviewed Card from a Card whose durable history was truncated out of the current locator list. That confirms the common S1/S3/S4 locator-truncation vector. S2's sibling-Card vector is related but is not needed to establish this verdict.

## Technical verdict

CONFIRMED_MATERIAL

## Why

The claimed “truncation-proof” Final gate proves consistency only against the history currently named by the Board. It does not prove that this locator set is complete relative to durable prior state.

Because the acceptance explicitly forbids silent observation loss, allowing a previously durable open observation to become invisible merely by removing its locator lets Final certify an incomplete history. This is load-bearing: it can turn an unreconciled observation into successful Final completion.

## Smallest relevant implementation boundary

The smallest defect boundary is the durable-history completeness contract around `tools/close_contract.py::verify_final_observation_reconciliation_from_board()` and the Task Board review-attempt history it consumes.

The Final gate needs a durable way to establish that the selected Card's canonical review-attempt history is append-only/complete, rather than treating the current locator list as self-authenticating completeness proof.

## Useful future regression-test shape

1. Board revision N durably lists R01 containing open O1; later current Board omits R01 while the R01 artifact remains durable -> Final must fail closed and cannot reconcile vacuously.
2. Removal or replacement of a previously durable review-attempt locator without an authorized append-only successor/history proof -> Recovery.
3. Truly never-reviewed Card with an independently proven empty history -> empty reconciliation may complete when otherwise legal.
4. Current complete locator history with O1 open and proposal omitting O1 -> reject.
5. Current complete history with O1 terminally reconciled and proposal exactly matching the derived disposition -> accept.
6. A separate workstream-level test should cover the shadow reviewers' sibling-Card concern if Final semantics require one invocation to cover all Cards; that sibling is not necessary to reproduce the confirmed locator-truncation defect.
