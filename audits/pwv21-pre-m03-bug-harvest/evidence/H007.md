## Claim under test

An unfinished Plan Review with verdict `in_progress` can pass validation and then be routed with RED correction semantics even though canonical Plan Review defines only `pending / green / red` and no terminal RED evidence exists.

## Expected canonical semantics

`workflow/PLAN_REVIEW.md` defines the Plan Review attempt lifecycle as `pending / green / red`. RED is a terminal review outcome that returns to Planning for correction classification. An unfinished attempt must therefore remain owned by review or fail closed; it must not acquire RED correction authority.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. Shared `validate_review()` explicitly accepts `{"pending", "in_progress", "green", "red"}`.
2. For non-terminal verdicts, including `in_progress`, the validator requires only an empty `evidence_path`; therefore an unfinished attempt with no terminal evidence is structurally valid.
3. `validate_plan_review()` calls the shared validator but does not narrow the Plan Review verdict domain to the canonical `pending / green / red` set.
4. In the frozen-plan routing branch after premium B is satisfied, the router explicitly handles `pending` as the Plan Review obligation and `green` as Planning consumption.
5. Every remaining accepted verdict falls through to an unconditional `route/planning` result whose reason is `RED Plan Review returns to Planning for correction classification`.

Therefore a valid `in_progress` record follows the RED path even though no RED verdict or terminal evidence exists. This matches source finding S003-F03 exactly.

## Technical verdict

CONFIRMED_MATERIAL

## Why

The defect is a direct domain/dispatch mismatch across two production boundaries: the shared review validator admits an extra non-terminal state, while the Plan Review router assumes that anything not pending or green is RED. The canonical Plan Review contract does not grant `in_progress` RED semantics.

This is material because the resulting route changes authority: an unfinished independent review is converted into Planning correction authority instead of remaining an active review obligation or failing closed.

## Current candidate check

- `validate_review()` still accepts `in_progress`;
- `validate_plan_review()` still does not narrow the Plan Review verdict domain;

- after those two predicates do not match, the router still unconditionally returns Planning with the RED-correction reason.

Moving pending/green checks into the PWv2.1 policy kernel therefore preserves, rather than closes, the original fall-through.

## Smallest likely defect boundary

The smallest boundary is the Plan Review verdict contract at the shared-validator/router seam. Either Plan Review validation must reject unsupported shared-review states, or routing must exhaustively distinguish `red` from every other accepted state and fail closed for contradictions. This review does not implement either repair.

## Useful regression-test shape

Use an otherwise valid frozen Planning fixture with premium B satisfied and an exact Plan Review subject, then vary only the Plan Review verdict:

1. `pending` with empty evidence -> routes to Plan Review.
2. `green` with terminal evidence -> routes to Planning for GREEN consumption.
3. `red` with terminal evidence -> routes to Planning for RED correction.
4. `in_progress` with empty evidence -> must not receive RED semantics; reject/recover or route to the explicitly documented active-review lifecycle if one is added.
5. Any other verdict -> fail closed.

The regression should assert both disposition/obligation and reason so a generic fall-through cannot masquerade as RED.
