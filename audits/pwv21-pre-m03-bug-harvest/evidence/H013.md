## Claim under test

Close review reuse may incorrectly treat a smaller current acceptance set as unchanged review coverage: a prior GREEN review over `{A,B,C}` can be reused for current `{A,B}` when content/behavior fingerprints are unchanged and affected compatibility verification is GREEN.

## Expected canonical semantics

The assigned historical `workflow/CLOSE.md` explicitly allows reuse when covered content/behavior is unchanged, affected compatibility verification is GREEN, and the **current acceptance is fully covered by the GREEN review**. The same section requires a new subject when covered content, behavior, or required acceptance materially changes.

The technical question is therefore whether a strict acceptance-set shrink is forbidden exact-surface drift, or intentionally legal stronger-prior-coverage reuse.

## Observed historical-subject behavior

At `4fb4bfb7d7b1481d6f347c182fc96a5a1135e045`:

1. `tools/close_contract.py::classify_review_coverage()` declares a material acceptance change only when `current.acceptance` is **not** a subset of `reviewed.acceptance`.
2. With reviewed `{A,B,C}`, current `{A,B}`, unchanged content/behavior fingerprints and GREEN affected compatibility, the helper returns `reuse_green_review`.
3. The repository test `test_stronger_review_coverage_may_be_reused` explicitly asserts that exact subset behavior.
4. This is consistent with the adjacent canonical sentence permitting reuse when the current acceptance is fully covered by the prior GREEN review. A superset prior review fully covers the smaller current set.
5. The source finding relies on reading the later phrase “required acceptance materially changes” as requiring set equality even for removal. The same canonical section and the explicit positive test do not establish that interpretation.

The observed behavior is real, but the assigned authority does not establish that it is a correctness defect.

## Technical verdict

REJECTED

## Why

The reproducer demonstrates intended coverage semantics rather than a violation of the historical contract. The canonical Close rule uses a coverage relation, not equality: reuse is permitted when the current acceptance is fully covered by the prior GREEN review, content/behavior are unchanged, and affected compatibility is GREEN.

A prior review of `{A,B,C}` is stronger with respect to the remaining `{A,B}` obligations than a review of `{A,B}` alone. The exact historical test deliberately preserves that interpretation.

Changing the helper to require acceptance-set equality would therefore be a policy change or clarification, not a repair justified by H013's assigned historical authority.

## Useful future regression-test shape

Preserve the currently documented coverage semantics unless authority changes:

1. Reviewed `{A,B,C}`, current `{A,B}`, same content/behavior, compatibility GREEN -> reuse GREEN.
2. Reviewed `{A,B}`, current `{A,B,C}` -> new review subject.
3. Any covered content or behavior fingerprint change -> new review subject.
4. Subset coverage with compatibility not GREEN -> fail closed.
5. If future authority explicitly requires acceptance-set equality, replace case 1 with a new-review expectation and bind that change to the new authority.

## Limitations

The phrase “required acceptance materially changes” can be read more strictly than the helper implements. H013 is rejected because the same canonical section also states the positive “fully covered” reuse rule and the repository has an explicit positive test for stronger prior coverage. The assigned historical authority therefore does not prove that subset reuse is forbidden.
